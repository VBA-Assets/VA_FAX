# samples/README.md — 機能確認用サンプルPDF一覧

本フォルダのPDFは `make_samples.py` により生成された機能確認用サンプルである。
再生成する場合は `python make_samples.py` を実行する（要 reportlab / pypdf / Pillow）。

すべてのサンプルはツールが自動生成した架空の内容であり、機密情報を含まない。

**前提**：下表の「主な検証対象要件」の期待結果は、標準プロファイル（MOT/FAX：上限3MB・A4のみ・横向き非対応）を選択した場合を基準とする。プロファイルにより期待結果は変わる。例：sample04の横向きページはMOVFAXプロファイルでは回転されない（横向き対応のため）。sample10（11ページ）は秒速FAX送信プロファイルではページ数上限（10ページ）超過のエラー（F-14）となる。プロファイル別の期待値はテストコード側でプロファイル定義から導出すること。

## 補足

- sample08・09の「スキャン風ページ」は、文字が画像として格納されたページ（テキストレイヤーなし・紙地のムラあり）を模擬したものである。F-09の自動判定がこれを文字・線画調と判定し単純閾値を適用することが、誤差拡散によるG4圧縮効率崩壊（サイズ膨張）を防ぐ要点となる。
- sample10は、結合PDFの一部ページのみが容量超過の原因となる状況の再現を目的とする。変換後、テキストページの解像度が維持されていることを変換レポートで確認すること。
- 破損PDF（F-20のもう一方の検証対象）は、任意のサンプルの先頭数バイトを削る等で別途作成する（意図的な破損ファイルはリポジトリに含めない）。
- sample12は、輝度ヒストグラムだけでは白背景との区別がつきにくい淡色（無彩色ではない）の罫線を検出できるかを検証する。単純閾値（Otsu法によるグレースケール二値化）はこの種の線を白へ切り詰めてしまうため、色の有無（RGB各チャンネルの差）を先に判定し、色があれば誤差拡散を選ぶ。
- sample13は、対応外サイズのページが正規化先サイズ（A4）より小さい場合の挙動を検証する。用紙正規化は「正規化先サイズに収める」処理であり、大きいページは縮小するが、小さいページをあえて拡大する必要はない（原寸のまま中央配置すれば足り、出力ページ自体はA4サイズになる）。
