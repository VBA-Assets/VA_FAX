## 1. 背景と目的

### 1.1 背景

インターネットFAXサービスは、PDF等のファイルをアップロードしてFAX送信を行うが、送信可能なファイルにはサービスごとに公表仕様上の制約がある（例：MOT/FAX〔バルテック〕はPDF/TIFF・最大3MB・A4のみ・カラー未対応、eFaxは合計1MBまで、メッセージプラスは1ファイル5MBまで等）。法律事務所等の利用現場では、Word等で作成した文書やスキャンした資料をこれらの制約に適合させるために相当な手作業が発生していると推察される（実際、eFax利用者には容量制限のため50枚の資料を分割送信した例が報告されている）。

また、テキストデータを含むPDF（Word等から直接出力したPDF）は、FAXサービスのサーバー側で行われるフォント再レンダリング処理に起因して、フォント置換や送信失敗が発生する場合があると考えられる（MOT/FAXの公表注記等。第4.3章参照）。全ページをラスタライズする本ツールの方式は、サービスを問わずこの種の問題を回避する。

### 1.2 目的

インターネットFAXにアップロードするPDFファイルの準備作業を省力化するWindows用デスクトップツールを開発し、VBAアセットで公開することにより、法律事務所をはじめとするFAX利用事業所のIT化を推進する。送信制約の数値はインターネットFAXサービスごとに異なるため、制約値は「サービスプロファイル」として切替可能な構造とする（第5.9章）。第一版で検証対象とする標準プロファイルはMOT/FAX（バルテック）である。

### 1.3 ツールの中核価値

1. 任意のPDFを、選択したインターネットFAXサービスの制約に適合する形式（標準プロファイルのMOT/FAXでは A4・モノクロ・3MB以内の画像PDF）に自動変換する。
2. 全ページをラスタライズ（画像化）することで、テキストデータ付きPDFのフォント問題・送信失敗リスクを構造的に排除する。
3. Python実行環境を持たない事務職員が、ダウンロード後すぐに使える形（単一exe）で提供する。

## 4. 標準プロファイル（MOT/FAX）の送信仕様

### 4.1 公式仕様（一次資料により確認済み）

出典：バルテック MOT/TEL公式サイト 機能ページ（https://www.mot-net.com/mottel/fax ）

| 項目 | 仕様 |
|---|---|
| 対応ファイル形式（送信） | PDF、TIFF |
| ファイルサイズ | 最大3MBまで |
| 対応サイズ（送信） | A4のみ |
| カラー対応 | 送受信ともカラーFAX未対応 |
| 同時送信 | 1送信 |
| 備考 | 「相手に送られる文字フォントが変わる場合があります」との注記あり |

### 4.2 本ツールが採用する出力仕様

上記制約を確実に満たすため、標準プロファイル（MOT/FAX）における出力仕様を以下のとおり定める。容量上限・用紙サイズ等の数値は選択中のサービスプロファイルにより変わる（第5.9章。以下の各要件における「3MB」「A4」等の記載は、標準プロファイルの値の例示である）。

| 項目 | 出力仕様 | 根拠 |
|---|---|---|
| 形式 | PDF（画像のみ・テキストデータなし） | 公式対応形式。ラスタライズによりフォント問題を排除 |
| 用紙サイズ | A4（210×297mm）縦置き | 公式対応サイズ |
| 解像度 | 200dpi（初期値。容量超過時に段階的に低減） | G3 FAXファインモード相当 |
| 色 | 1bit白黒（デフォルト）または8bitグレースケール（オプション） | カラー未対応制約。グレースケールは4.3参照 |
| 圧縮 | 二値化時：CCITT G4／グレースケール時：JPEG | 各色深度で最も容量効率が高い方式 |
| ファイルサイズ | 3MB以下（超過時は自動的に対処） | 公式上限 |

### 4.3 未確認事項（設計上の扱い）

以下はバルテックの公開資料で確認できておらず、確定情報ではない。

1. **グレースケールPDFの受理可否**：業界一般にはFAX送信サービスへのグレースケール入稿は標準的な運用だが、MOT/FAX固有の裏付けはない。→ デフォルトを1bit白黒（確実に受理される最も保守的な形式）とし、グレースケールはテスト送信推奨の注記付きオプションとする。
2. **テキストデータ付きPDFの送信可否**：送信失敗するとの利用経験の記憶があるが、一次資料の裏付けはない。→ 本ツールは常に画像PDFを出力するため、真偽にかかわらず問題を回避できる。
3. **ページ数上限・暗号化PDFの扱い・対応PDFバージョン**：公開資料に記載なし。→ 暗号化PDFは処理対象外としてエラー扱い（第6.6章）。

## 5. 機能要件

### 5.1 入出力（F-01〜F-03）

- **F-01** 入力は1件以上のPDFファイルとする（件数の上限は設けない。実質的な上限は選択中プロファイルのページ数・容量制約〔F-13・F-14〕が担う）。複数件入力された場合は、入力欄の表示順（追加した順）に**1つのPDFへ結合して**変換する（FAX送信時は送信票PDFに本文PDFを添付するのが通常の運用であり、事前にPDF編集アプリで結合する作業を本ツール内で完結できるようにする）。結合はメモリ内でのみ行い（N-06）、入力ファイルは変更しない（F-03）。出力が1送信分の単一ファイルとなる点は従来どおりであり、複数ファイルをそれぞれ別のFAXへ変換する一括処理（フォルダ一括処理）は行わない（MOT/FAX・メッセージプラス等、多くのインターネットFAXサービスが1送信1ファイルの運用であることに対応）。暗号化・破損ファイルが含まれる場合は、どのファイルが原因かを明示してエラー表示する（F-20・F-21。ログにはファイル名を記録しない〔F-24〕）。
- **F-02** 出力は単一のPDFファイルとする（容量超過時の処理方式〔F-13〕として「分割して再実行」が選択され、かつ実際に分割が発生した場合を除く。この場合の出力ファイル名の扱いはF-13参照）。出力ファイルの初期値（保存先フォルダ・ファイル名）は、変換の既定設定（F-26）の次の2方針から自動決定し、画面上でユーザーが変換ごとに変更可能とする。
  - 出力先方針：「入力ファイルと同じフォルダ」（初期値）または「固定フォルダ」。
  - ファイル名方針：「入力ファイル名＋『_fax』」（初期値）または「入力ファイル名と同一」。複数件入力時の「入力ファイル名」および「入力ファイルと同じフォルダ」は、先頭（1件目）の入力ファイルに基づく。ただし「入力ファイルと同じフォルダ×入力ファイル名と同一」の組合せは入力ファイルの上書きとなるため設定画面で選択不可とし、設定の組合せにかかわらず出力パスがいずれかの入力パスと一致する場合は実行時にエラーとする（F-03の非破壊原則）。
  - 出力先に同名ファイルが既に存在する場合は、変換実行時に上書き確認を表示する（F-16に整合）。
  - 固定フォルダが変換実行時に存在しない場合（共有フォルダ未接続等）は、別の場所へのフォールバック出力を行わず、設定の確認を促す平易なエラーで停止する。
- **F-03** 入力ファイルは変更しない（非破壊処理）。

### 5.2 事前診断（F-04〜F-06）

- **F-04** 入力ファイルの追加・削除の都度、以下を自動判定し、画面に表示する（複数件入力時は結合後のPDF全体を対象とし、ページ番号も結合後の通し番号で表示する）。
  1. 総ページ数（プロファイルにページ数上限がある場合は上限との照合結果も表示）
  2. 各ページの用紙サイズ（選択中プロファイルの対応外サイズのページがある場合はページ番号とサイズを明示。例「8ページ中2ページがB4です（3、5ページ目）」）
  3. カラー／グレースケール／白黒の別（ページ内画像・描画内容から判定）
  4. テキストデータの有無
  5. 入力ファイルサイズ（複数件入力時は結合後のサイズとし、その旨を表示する。あわせて入力ファイル数と「上から順に結合して変換される」旨を表示する）
- **F-05** 処理オプション（用紙正規化・圧縮方式等）は、事前診断の結果によって自動でON/OFFを切り替えない。既定設定（F-26）の固定値をそのまま画面の初期状態とする（F-06と同じ考え方。用紙正規化は対応サイズに含まれるページには何も作用しないため、常に有効にしておくこと自体に副作用がない。診断結果はユーザーが手動判断する材料として提示するに留める）。用紙正規化を無効にした場合、対応外サイズのページを含む変換はF-14により停止する。
- **F-06** 圧縮方式（二値化／グレースケール）は常に二値化を既定とする。診断結果には、判断材料としてページ別のカラー／グレースケール／白黒の判定を表示する（F-04）が、文書内容による自動推奨は行わない（二値化はG4圧縮との相性がよくFAXで最も一般的な原稿形式である一方、グレースケールは送信時にサービス側で白黒へ自動変換される際に黒つぶれ・白飛びが生じる場合があるため。詳細はprimary-sources.md参照）。写真・図版中心の原稿でグレースケールを用いるかどうかは、診断結果を踏まえてユーザーが判断し選択する。

### 5.3 変換処理（F-07〜F-13）

- **F-07 ラスタライズ**：全ページを200dpi（初期値）でビットマップ化する。出力PDFはテキストデータを一切含まない。入力PDFの文書情報（作成者・タイトル・作成アプリ等のメタデータ）も出力に引き継がない（出力はページ画像から新規に構築するため構造的に引き継がれない。守秘設計の一部として自動テストで保証する）。
- **F-08 用紙正規化（プロファイル準拠）**：選択中プロファイルの対応用紙サイズリストに**含まれない**ページのみを、プロファイルが規定する正規化先サイズ（既定はA4 210×297mm）のキャンバスに中央配置する。アスペクト比は維持する。正規化先サイズより**大きい**ページは縮小するが、正規化先サイズより**小さい**ページはあえて拡大しない（原寸のまま中央配置する。文書の実寸を不必要に拡大する必要はないため）。いずれの場合も出力ページ自体は正規化先サイズ（A4等）になる。対応サイズに含まれるページは寸法を変更せずそのまま通す（例：MOVFAXプロファイルではB4・A3ページを縮小しない）。
  - 縮小を伴う場合（B4→A4 約82%、A3→A4 約71%等）は、縮小率と判読性低下の注意を事前診断欄に表示する。
  - サイズ判定には±2mmの許容誤差を設け、対応サイズに実質一致するページに不要な処理を行わない。レターサイズ（215.9×279.4mm）は対応サイズに含まれない限り正規化対象とする。
  - 横向き（ランドスケープ）ページの扱いはプロファイルの横向き受理可否属性に従う。横向き非対応のプロファイル（MOT/FAX等）では90度回転して縦置きに収める（原寸維持。縮小配置方式は採用しない）。横向き対応のプロファイル（MOVFAX等）では回転しない。
- **F-09 二値化（デフォルト圧縮方式）**：グレースケール変換後に1bit白黒化する。ディザ方式は「自動」「誤差拡散」「単純閾値」から選択可能とし、初期値は「自動」とする。
  - **自動選択時は、まずページに色（無彩色でない画素）が含まれるかを判定し、次に輝度ヒストグラムを分析して方式を決定する**。淡い色のみで印刷された罫線・枠等を含むページ（銀行帳票等に見られる、輝度だけでは白背景とほぼ区別できない淡色の線。単純閾値では白と判定され消えてしまう）は、色の存在をもって誤差拡散を適用する。無彩色のページは、文字・線画調（輝度分布が白黒二極に集中）には単純閾値（閾値は大津の判別分析法によりページごとに自動決定）、写真・グラデーション調には誤差拡散ディザを適用する。
  - 本方式の趣旨：スキャン由来のページ（文字が画像として格納され、紙の地色・照明ムラを含む）を誤差拡散でディザリングすると、背景が無数の微細な点に変換されてG4圧縮の効率が崩壊し、ページサイズが著しく膨張する。単純閾値であれば背景は白に飛び、文字は明瞭に残り、サイズも最小となる。結合PDFではWord由来ページとスキャン由来ページの混在が通常であるため、ページ内容に応じた方式選択を既定動作とする。
  - 自動選択で適用した方式は、ページごとに処理ログ（F-17）および変換レポート（F-25）に記録する。
  - 閾値・パラメータは小さい文字（条文・約款等）が潰れないことを優先して調整する。
  - OCRによるテキスト復元は行わない（認識誤りにより文書の記載内容が変わるリスクがあるため。出力は画像PDFでありサイズ面でも不要）。
- **F-10 グレースケール（オプション圧縮方式）**：8bitグレースケール＋JPEG圧縮で出力する。JPEG品質は「高・中・低」から選択可能とし、初期値は「中」とする。選択時、UI上に「サービス側で黒つぶれ・白飛びが起こる場合があります。実際に送信してご確認ください」との注記を表示する（他社インターネットFAXサービスの公式情報に基づく。primary-sources.md参照）。
- **F-11 圧縮方式は排他選択**：二値化とグレースケールはラジオボタンによる排他選択とする。
- **F-12 PDF再構成**：二値化時はCCITT G4圧縮、グレースケール時はJPEG圧縮で画像を格納したPDFを生成する。
- **F-13 容量制御（ページ単位の適応制御）**：出力がプロファイルの容量上限（標準プロファイルでは3MB。本要件内の記載は同値を例とする）を超えた場合、容量超過時の処理方式（既定設定〔F-26〕で選択。初期値「解像度・品質を下げて再実行」）に従って常に自動で対処する（対処しない、という選択肢は設けない。「解像度・品質を下げて再実行」では画質が、「分割して再実行」では出力ファイル数が変わるだけで、いずれも送信可能な出力を得られるため、対処自体をOFFにする利点がない）。全ページ一律の解像度低減は行わない。
  1. 「解像度・品質を下げて再実行」：ページごとの出力サイズを計測し、容量超過の原因ページ（出力サイズの大きいページ）を特定したうえで削減する。
     1. 削減方式（既定設定〔F-26〕で選択。初期値は「原因ページのみ」）に従い、削減対象を選ぶ。
        - **原因ページのみ**：最もサイズの大きいページから順に、当該ページのみ削減を適用して総容量を再計測する。容量超過の原因でないページの解像度・品質は変更しない（結合PDFにおいて、一部の写真・図版ページが原因で文字ページまで劣化させることを防ぐ）。原因が1ページに集中している場合、そのページだけで解像度・品質を大きく下げる必要が生じる場合がある。
        - **全体を均等に**：削減可能な全ページを1段階ずつ均等に削減してから総容量を再計測する。原因ページの下げ幅は緩和されるが、原因でないページも画質が落ちる。
        - いずれの方式でも、二値化時は解像度を段階的に低減（200→150→120dpi）、グレースケール時はJPEG品質を低減し、なお超過時は解像度を低減する。
     2. すべてのページが下限（120dpi）に達してもなお容量上限を下回らない場合はエラーとし、ページ分割等の対応をユーザーに案内する。
  2. **「分割して再実行」**：解像度・品質は落とさず、ページの順序を維持したまま、各ファイルが容量上限に収まる単位で複数のPDFに分割する（重要書類等、画質より完全性を優先したい場合の選択肢）。
     - 出力ファイル名は「（元のファイル名）\_1of3.pdf」のように連番＋総数のサフィックスを付与する。分割が発生しない（全体が既に容量上限以下の）場合は、従来どおり単一ファイル・元のファイル名のまま出力する。
     - 1ページ単体で容量上限を超える場合（情報量の多いページが単独でも収まらない場合）に限り、そのページのみ「解像度・品質を下げて再実行」と同じ段階的削減を適用する。全段階を尽くしてもそのページ単体で収まらない場合はエラーとする。
     - 出力先に、分割後と同じファイル名（連番サフィックス付き）のファイルが既に存在する場合は、変換を行わずエラーとし、該当ファイルの移動・削除または出力ファイル名の変更を案内する（分割の有無・個数は変換結果が出るまで確定しないため、F-02の上書き確認とは別に、書き込み直前に検証する）。分割後のファイル名が入力ファイルと一致してしまう場合（入力ファイル名が偶然「\_1of2」等の形式である場合）も、同様に書き込み直前に検証しエラーとする（F-03の非破壊原則）。
     - 分割ファイル群の書き込みが途中で失敗した場合、書き込み済みの一部のパートだけが残ると利用者が不完全なセットと気づかずに送信する恐れがあるため、当該実行で書き込んだ分は削除する。削除できなかった場合はファイル名を明示して手動削除を案内する。
     - 分割が発生した場合、ベース名（無サフィックス）のファイルには書き込まれない。同名の古いファイルが出力先に存在する場合は、完了メッセージで「今回の出力では更新されていない」旨を注意喚起する（削除はしない。本ツール以外で作られたファイルである可能性を排除できないため）。
     - 変換レポート（F-25）は分割後のファイルごとに、そのファイルに含まれるページのみを対象として生成する。
  3. ページごとの最終解像度・品質は処理ログ（F-17）および変換レポート（F-25）に記録し、どのページにどの削減が適用されたかを利用者が検証できるようにする。
  4. いずれの処理方式でも対処しきれない場合（「解像度・品質を下げて再実行」で全ページが下限に達してもなお超過する場合、または「分割して再実行」で1ページ単体が下限まで縮小してもなお超過する場合）は変換を行わずエラーとし、具体的な対処案内（二値化時はディザ方式を「単純閾値」へ切替、グレースケールへの切替の各提案）を表示する（F-21）。

### 5.4 サイズ検証とエラー停止（F-14）

- **F-14 送信可否検証**：以下の場合、変換を行わずエラーで停止する。
  - **ページ数上限検証**：選択中プロファイルにページ数上限がある場合（秒速FAX送信=10ページ、MOVFAX=255ページ等）、入力PDFのページ数（複数件入力時は結合後の総ページ数）が上限を超えるときはエラーとし、ファイルの分割を案内する（本ツールはページの削除・分割を行わない）。事前診断（F-04）でも超過を警告表示する。
  - **用紙サイズ検証**：用紙正規化がOFFの状態で、選択中プロファイルの対応外サイズのページを含むPDFの変換を実行しようとした場合、変換を行わずエラーで停止し、「（プロファイル名）の対応外サイズのページが含まれるため送信できません。用紙の正規化を有効にしてください」と表示する。プロファイルの対応外サイズを含むPDFは出力しない。（※本項の主語の変更に伴い、以降の「F-14」への参照はこの送信可否検証全体を指す）

### 5.5 GUI要件（F-15〜F-19）

- **F-15** GUI構成は以下とする。ウィンドウタイトルは「VA FAX」とする。
  1. 選択中プロファイル名と主要制約値の表示（例「対象サービス：MOT/FAX（上限3MB・A4）」。F-28に基づき選択UIは置かない）
  2. 入力ファイル選択（1行1ファイルで表示するスクロール可能な複数行テキストボックス＋「入力元...」ボタン。ドラッグ＆ドロップ対応）。入力済みの状態で「入力元...」（複数選択可）またはドロップを行うと末尾に追加される（F-01。送信票の後に本文を追加する運用）。件数のハード上限は設けないが、一度の操作（ドロップ・ダイアログ選択・貼り付け）で多数件（10件超。サービス制約値ではないUI上の設計値）を追加する場合は、「◯件のファイルを追加し、合計◯件を結合します。よろしいですか？」の確認を挟む（フォルダ内の大量PDFを誤ってまとめてドロップした場合等の歯止め）。この欄は文字を編集するテキストボックスとしてではなく、行単位のファイル一覧として扱い、削除・並べ替え・カット・コピーはいずれも「選択中の行」に対して行う（操作の対象が常に反転表示で見えている状態を保つ）。文字の直接入力・部分編集は受け付けない（表示中の一覧と実際の変換対象の食い違いによる誤変換を防ぐ）。個々の操作は以下のとおりとする。
     - **行の選択**：クリックでその行全体を選択する。未選択の状態では削除・並べ替え・カット・コピーのいずれも動作しない。複数行はShift+クリック・Shift+ドラッグ、全件はCtrl+Aで選択する。上下矢印キー・PageUp／PageDown・Home／Endは選択行そのものを動かし（Shift併用で範囲を広げ）、キーボードのみの操作でも対象が常に見えている状態を保つ。最終行より下の余白のクリック、およびEscapeキーで選択を解除する。文字単位の入力位置には意味がないため、点滅する挿入カーソルは表示しない。
     - **削除**：選択中の行をDeleteキーまたはBackSpaceキーで一覧から取り除く（後述のドラッグによる取り除きも同じ扱い）。いずれも入力ファイル自体は変更しない（F-03）。
     - **並べ替え（ドラッグ）**：行を押してそのまま動かすと、その行（複数行を選択している状態でその範囲内を押した場合は選択中の塊全体）が移動する。押した時点でその行が選択されるため、選択と移動を1動作で行える。ドロップ先の挿入位置は行の境界に沿った線（アクセント色）で示し、ポインタが欄の上端・下端にある間は一覧を自動スクロールする。ドロップ位置が移動元の範囲内であれば並べ替えを行わない。移動後は移動した行を選択状態にして移動先を示す。
     - **ドラッグによる取り除き**：テキストボックスの外へ持ち出して放した場合は、選択中の行を一覧から取り除く（確認は挟まない〔Ctrl+Zで戻せるため〕）。持ち出している間は挿入位置の線を消し、マウスカーソルを「矢印＋ゴミ箱」（同梱のresources/trash.cur。build/make_cursor.pyで生成）に変えて「放すと取り除かれる」ことを示す。カーソルを読み込めない環境では標準の✕カーソルを用いる。末尾へ移動しようとして枠からわずかにはみ出した場合等を取り除きと誤判定しないよう、枠の縁から余裕（16px。自動スクロールの反応域より広く取る）を越えた場合のみ「外」と判定する。ドラッグ中のEscapeキーでその操作（並べ替え・取り除き）を取りやめる。
     - **カット・コピー・ペースト**：選択中の行をCtrl+X／Ctrl+Cでクリップボードへ取り出し、Ctrl+Vで貼り付ける。ペーストの挿入位置は選択中の行の前とし、何も選択していない場合は末尾に追加する。貼り付けた行は選択状態にする。この欄でカット・コピーした行のほか、実在するPDFファイルのパスのテキストも貼り付け可能。認識できない内容の貼り付けはエラー表示して拒否する。
     - **取り消し**：一覧への変更（追加・削除・カット・ペースト・並べ替え）はCtrl+Zで直前の状態に戻せる（履歴の残っている限り繰り返し遡れる。進む方向のやり直し〔Redo〕は設けない。メイン画面内のどこにフォーカスがあっても有効とする〔プレビュー操作後等でも効くように。ただし出力ファイル欄等の文字入力欄と設定ダイアログでの押下は対象外〕）。

     ファイルの追加・削除・並べ替えの都度、事前診断（F-04）とプレビュー（F-30）を更新する。
  3. 出力ファイル指定（テキストボックス＋「出力先...」ボタン。初期値はF-02の方針から自動設定。画面上の変更は当該変換限りとし、次のファイル選択時に方針から再計算する。「出力先...」の保存ダイアログには現在の出力ファイル名を初期表示し、毎回の手動入力を不要にする。同ダイアログではOS標準の上書き確認を行わない〔上書き確認は変換実行時に行う（F-02）。「分割して再実行」ではここで指定した名前は分割時のベース名であり、実際にその名前で書き込まれるとは限らないため〕）
  4. 事前診断結果の表示欄
  5. 処理選択欄：選択肢の数が少ない項目から順に「圧縮方式」（見出し付き。ラジオボタン：二値化・グレースケール、各詳細設定〔ディザ方式・JPEG品質〕）→「容量超過時の処理方式」（見出し付き。ラジオボタン2択「解像度・品質を下げて再実行」〔削減方式ドロップダウンを併設〕／「分割して再実行」。常に自動で対処するため、対処自体のON/OFFチェックボックスは設けない〔F-13〕）→「用紙正規化」（チェックボックス）→「変換レポートを出力先フォルダに保存する」（チェックボックス）の順に並べる。
  6. 変換実行ボタン（表示文言は「変換して出力」とし、変換だけでなく出力ファイルへの保存まで行うことを明示する）
  7. 進捗バーおよび処理ログ表示欄
  8. メニュー：設定（プロファイル変更〔F-28〕・変換の既定設定〔F-26〕）
  9. 配色・見た目はフラットデザインとし、Microsoft Office系ダイアログに近い配色・質感（ニュートラルな灰白色の地に、ホバー・フォーカス時のみ青系を差し色として使う）を採用する。立体的な縁取り・グラデーション等の装飾は用いない。色・スタイルの定義は`src/gui/theme.py`に集約し、メイン画面・各設定ダイアログ・プレビュー欄で共通の配色を用いる。ボタンは通常時ニュートラルな地色とし、ホバー時に淡い青、押下時に濃い青へ変化する。各コマンドボタンには常時、細い枠線を表示する（既定は灰色）。主要な操作ボタン（変換して出力・決定・保存）は、地色を塗りつぶすのではなく枠線をアクセント色にすることで常時強調し、他のボタンと区別する。
- **F-16 実行前確認の原則**：ファイル内容を変更するすべての処理は、実行前にチェックボックス／ラジオボタンによるユーザーの明示的な選択を経る。各選択肢には処理の副作用（「カラー・階調情報が失われます」等）を併記する。
- **F-17** 処理ログには、ページごとの処理内容、再試行の発生（「200dpiで3.4MB超過→150dpiで再生成→2.1MB」等）、最終的な出力仕様を表示する。
- **F-18** 変換完了後、出力ファイルの保存先フォルダを開くボタンを表示する。
- **F-19** UIの文言は、複数件の入力が「結合されて1送信分の1ファイルになる」こと（複数ファイルをそれぞれ別のFAXへ変換する一括処理ではないこと）、および送信操作自体は各FAXサービス側で行うことが明確に伝わる表現とする。この2点は関連性のない別個の事実であるため、無理に1つの文にまとめず、それぞれ最も伝わる箇所で案内する。「結合されること」は、入力欄のプレースホルダー文言と事前診断欄の表示（「上から順に結合して変換します」。F-04）で伝える。「送信操作は別途行うこと」は、画面下部に常時表示する注記で伝える。

### 5.6 エラー処理（F-20〜F-22）

- **F-20** 暗号化（パスワード付き）PDF、破損PDFは変換せずエラー表示する。
- **F-21** すべてのエラーは、事務職員が対処方法を判断できる平易な日本語で表示する。
- **F-22** 予期しない例外発生時も、スタックトレースを直接表示せず、要旨と問い合わせ先（VBAアセット）の案内を表示する。

### 5.7 設定の永続化（F-23）

- **F-23** 設定ファイル（JSON形式、保存先 `%APPDATA%\VA_FAX\settings.json`）に以下を保存する。
  - 前回使用した入力フォルダのパス（入力ファイル選択ダイアログの初期表示フォルダとする）。出力側ダイアログの初期位置は、出力先方針が「固定フォルダ」の場合は固定フォルダ、「入力ファイルと同じフォルダ」の場合は入力ファイルのフォルダとする（前回出力フォルダの保存は廃止し、その役割は既定設定の出力先方針が担う）。
  - 選択中プロファイル（F-28）・変換の既定設定（F-26）等のUI状態。
  - 設定ファイルが存在しない場合、または破損している場合は、既定値（ユーザーの「ドキュメント」フォルダ・初期既定設定）にフォールバックする。
  - 文書に関する情報は保存せず、外部への送信は一切行わない（N-01・N-06に整合）。
  - settings.json は手動編集にも耐える平易な構造とし、項目仕様をREADMEに記載する。管理者が設定済み settings.json を事務所内の複数PCへコピーすることで、プロファイルと既定設定を一括配布できる（F-28の配布方式を既定設定にも拡張）。

### 5.8 ログ・レポート・既定設定（F-24〜F-26）

本節の各機能は、後述の守秘設計原則（N-06）に従う。

- **F-24 エラー・診断ログ**：`%APPDATA%\VA_FAX\logs\` に日付別のログファイルを保存する。
  - ログには、**入力・出力のファイル名およびパスを一切記録しない**（デバッグモードのような切替も設けず、常時この方針とする）。
  - 記録対象は、処理段階・エラー種別に加え、事前診断結果（総ページ数・各ページの用紙サイズ・カラー/グレースケール/白黒の別・テキストデータ有無・入力ファイルサイズ・暗号化検出の有無）、ページごとの解像度・二値化方式・再試行内容、予期しない例外発生時のスタックトレースとする。これらはファイル名・パス・文書内容そのものではないため、常時記録して差し支えない。
  - 本ツールはVBAアセットで公開され、利用者から問合せがあった際は「ログファイルを送ってください」と案内する運用を想定する。ファイル名を含まない前提のログのみで、事前診断結果とスタックトレースから原因の見当を付けられるようにする。
  - ログの保存件数・期間には上限を設け、自動的に古いものから削除する。
- **F-25 変換レポート**：変換実行ごとに、処理内容の記録（元ファイル名〔複数件入力時は結合順の全ファイル名〕・元サイズ〔同・合計サイズ〕・ページ数・適用処理・縮小率・容量超過時の処理方式・最終出力仕様）をテキストファイルとして**出力PDFと同じフォルダ**に保存するオプション（チェックボックス。既定値は変換の既定設定〔F-26〕により、初期状態はOFF。必要な利用者だけが有効にする）。ツールの管理領域（%APPDATA%等）への保存・蓄積は行わない。「分割して再実行」で複数ファイルに分かれた場合は、ファイルごとに、そのファイルに含まれるページのみを対象としたレポートを個別に生成する。
- **F-26 変換の既定設定**：処理オプションの既定値一式を、設定メニューの「変換の既定設定」画面で構成できる。設定項目は以下とし、settings.json（F-23）に保存する。既定設定には文書に関する情報を一切含めない。
  1. 出力先方針・出力ファイル名方針（F-02）
  2. 圧縮方式の既定値：「二値化（白黒・G4圧縮）」（初期値）／「グレースケール（JPEG圧縮）」（F-06により、文書内容による自動判定は行わないため2択とする。実際に使用する圧縮方式（G4／JPEG）を選択肢の表記に明示し、分かりやすくする）
  3. 用紙正規化を初期状態で有効にするかどうか（チェックボックス。初期値ON。F-05により、診断結果による上書きは行わない）
  4. ディザ方式（F-09）・JPEG品質（F-10）・容量超過時の処理方式「解像度・品質を下げて再実行」（初期値。削減方式「原因ページのみ」〔初期値〕／「全体を均等に」を含む）／「分割して再実行」（F-13）・変換レポート保存（F-25）の各既定値
  - 圧縮方式・用紙正規化・容量超過時の処理方式・変換レポート保存の各項目は、選択肢の表記および配置（圧縮方式は各選択肢の直下に詳細設定〔ディザ方式／JPEG品質〕を表示する等）をメイン画面の処理内容選択欄と同一とする（「既定値」の設定であることが文言からも明確になるよう、「常に」等の付加的な修飾語は付けない）。ただし、各選択肢の副作用を説明する「※」注記（F-15参照）は、既定値を設定するだけの本画面では判断材料として不要なため表示しない。
  - 画面上での手動変更は当該変換限りとし、次のファイル選択時に既定設定から再計算する。処理オプションの前回値の無条件自動引き継ぎは行わない（共有PCでの前任者設定の意図しない引き継ぎを防ぐ）。
  - 複数PCへの標準設定配布は settings.json のコピーによる（F-23・F-28）。名前付きプリセットの保存・呼び出し、およびエクスポート／インポート機能は設けない。

### 5.9 サービスプロファイル（F-27〜F-29）

- **F-27 プロファイル定義**：インターネットFAXサービスごとの送信制約（サービス名・最大ファイルサイズ・対応用紙サイズリストと正規化先・横向き受理可否・ページ数上限・カラー可否・解像度の初期値と下限・対応出力形式・利用者向け注記文言・確認状態〔検証済／参考〕と出典）を、コードから分離した外部定義（JSON）として持つ。プロファイル定義はexeに同梱するほか、`%APPDATA%\VA_FAX\profiles\` に追加配置されたプロファイルを読み込むことで、exeの再ビルドなしにサービスを追加できる構造とする。プロファイルには文書に関する情報を含めない（N-06に整合）。
- **F-28 プロファイル選択（初回選択・固定方式）**：1つの事務所が使用するインターネットFAXサービスは通常1つであることを前提に、プロファイルは初回に選択して固定する方式とする。
  - **初回起動時のみ**、プロファイル選択画面（「お使いのFAXサービスを選んでください」）を表示する。選択結果は settings.json に保存する。
  - **通常画面にプロファイル選択UIは表示しない**。画面には選択中のプロファイル名と主要制約値（例「対象サービス：MOT/FAX（上限3MB・A4）」）を表示するのみとし、事務職員の日常操作は「ファイル選択→変換実行」に限られるようにする。誤操作による意図しないプロファイル切替を構造的に防ぐ。
  - サービス変更（乗り換え等の稀な場合）は、メニューの「設定」からのみ行える。
  - settings.json のプロファイル指定項目は手動編集にも耐える平易な構造とし、項目仕様をREADMEに記載する。これにより、管理者が設定済み settings.json を事務所内の複数PCへ配布してプロファイルを固定する運用（実質的な設定ファイル配布方式）を可能とする。
  - 同梱プロファイルは以下の7つとする（各制約値の出典・確認日は docs/primary-sources.md に記録）。
  1. **MOT/FAX（標準・検証対象）**：本書第4.1章の公表仕様に基づく。PDF・最大3MB・A4のみ・モノクロ。
  2. **MOVFAX（公式仕様確認済）**：日本テレネット公式FAQの仕様表に基づく。PDF推奨・最大10MB・255ページ上限・A4/B4/A3（縦横どちらも対応）・画質はファインモード固定（200×200dpi）。
  3. **メッセージプラス（公式仕様確認済）**：公式FAQ・機能ページに基づく。PDF等・1ファイル5MBまで・用紙はサービス側でA4/B4に自動調整（ツール側の用紙検証は緩和）。印刷不許可・パスワード付きPDFは送信不可（本ツールの出力は制限なしPDFのため適合）。
  4. **eFax（参考・二次情報ベース）**：公式ヘルプで確認できるのは添付最大5件・パスワード付き不可・対応形式一覧まで。容量上限「合計1MB」は送信画面の表示文言を引用した複数の二次情報および実利用者の証言に基づく参考値であり、公式ウェブ文書では未確認。プロファイル選択時、UI上にこの旨の注記を表示する。本ツールの出力は単一PDFのため、出力1ファイルを1MB以内に収める制約として扱う。
  5. **秒速FAX送信（公式仕様確認済）**：Toones（Karigo）公式サイトに基づく。原則PDF（Word・Excel・画像は再現性が低く非推奨）・容量合計1MB以下・10ページ以内・A4サイズ標準。eFaxと並ぶ厳しい容量制限を公式に明記しているサービスであり、本ツールの容量制御の実益が大きい。
  6. **jFax（参考・容量は推定）**：eFaxの姉妹サービス（同じConsensus社）。送信可能ファイル形式一覧は公式ヘルプで確認済み（eFaxの公表表と同一）。容量上限は公式に記載がなく、同一インフラであることからeFaxと同じ「合計1MB」と推定した参考値とする。プロファイル選択時、UI上にこの旨の注記を表示する。
  7. **カスタム**：利用者が自身の契約サービスの公表仕様（容量上限・対応用紙等）を手動入力して使用する。プロファイル選択画面でカスタムを選び「決定」すると入力フォームを表示する。「お使いのサービスの公表仕様をご確認のうえ入力してください」との案内とともに、サービス名・最大ファイルサイズ（MB）・ページ数上限（空欄可）・対応用紙サイズ（A4・B4・A3・A5・レターから複数選択）・横向き受理可否・カラー対応等の備考を入力できる。解像度段階・JPEG品質段階・正規化先サイズ（A4）は他プロファイルと共通の既定値を用い、編集対象としない（複雑さを抑えるため）。入力値はプロファイルとして `%APPDATA%\VA_FAX\profiles\` に保存する（F-27の追加プロファイル配置方式により、当該JSONファイルのコピーで他のPCでも利用できる）。既にカスタムを選択中の状態で再度この画面を開いた場合も、入力内容を更新できる。
- **F-29 制約値のハードコード禁止**：容量判定（F-13）・用紙検証（F-08・F-14）・カラー処理（F-09〜F-11）・エラーメッセージ等、制約に依存するすべての処理は、選択中プロファイルの値を参照して動作する。「3MB」「A4」等の数値をコードに直接埋め込んではならない。
- 補足：実在サービス名を冠したプロファイルの同梱は、当該サービスの公表仕様（一次資料）を確認できたもの、または出典の性質を注記した参考プロファイル（eFax）に限る。各プロファイルの制約値はいずれも公表仕様に基づくものであり、実送信による動作検証は行っていない旨（MOT/FAXを含む。第9.2章の運用課題）を、README・操作マニュアル・VBAアセット掲載文に明記し、あわせて全サービス共通で初回のテスト送信を推奨する。

### 5.10 ページプレビュー（F-30）

- **F-30 プレビュー表示**：入力ファイル選択後、画面左側にプレビュー欄を表示する。複数件入力時は結合後のPDF全体を表示対象とし、入力ファイルの追加・削除の都度更新する（F-04・F-15と同期）。
  1. 全ページのサムネイル一覧を表示し、任意のページを選択すると同欄内に拡大表示する。
  2. プレビューは選択中の処理内容（圧縮方式・ディザ方式・用紙正規化）を反映した状態で表示し、処理内容の変更時に自動的に再生成する（この表示をステータス欄に「変換イメージ」と常時明示する）。拡大表示は本変換と同じ解像度（選択中プロファイルの既定dpi）で変換パイプラインを実行し、表示時にのみ画面サイズへ縮小する（低解像度で処理すると、二値化閾値の自動算出・ディザ方式の自動判定等の結果が本変換と食い違いうるため。表示時の縮小は完成した結果画像のズームであり判定には影響しない）。
  3. サムネイル・拡大表示の生成は表示範囲に応じた遅延読み込みとし、バックグラウンドスレッドで行いGUIの操作をブロックしない。
  4. プレビュー欄は他の画面領域との境界をドラッグして幅を変更できる（リサイズ可能）。
  5. PageUp／PageDownキーで前後のページへ、Home／Endキーで先頭・末尾ページへ表示を切り替えられる（キー操作は、サムネイルのクリック等でプレビュー欄を操作した後に有効となる。文書読込時にプレビュー欄が自動でキーボードフォーカスを取ることはしない〔入力ファイル欄でのDelete・Ctrl+Z等の操作を中断させないため〕）。拡大表示欄の上でのマウスホイール操作でも前後のページへ切り替えられる（サムネイル一覧側のホイールは一覧のスクロールに用いる。ホイール操作はフォーカス位置に依らず常時有効）。
  6. **変換完了後は、シミュレーションではなく実際に出力されたPDFそのものをプレビュー欄に表示する**（ステータス欄の表示を「変換イメージ」から「変換結果」に切り替えて常時明示する）。これにより、容量超過時の処理方式（F-13）による解像度・品質の低下を含む最終出力の内容を、出力ファイルを開かずに確認できる。「分割して再実行」により複数ファイルに分かれた場合は、最初のファイルのみを表示する（他のファイルは出力フォルダを開いて確認する）。処理内容の選択が変更された場合、または別の入力ファイルが選択された場合は、入力PDFのシミュレーション表示（変換イメージ）に戻る。
  7. 変換実行前のプレビューにおける残余の差異：サムネイル一覧はページ探し用の簡易表示であり低解像度で生成する（内容確認は拡大表示側で行う）。また、容量超過時の処理方式による調整結果（解像度低減の程度、実際に何ファイルに分割されるか等）、およびグレースケール時のJPEG品質は、変換実行前のプレビューには反映されない（全ページ処理後でないと確定しないため。いずれも変換完了後の実物表示〔前項〕で確認できる）。

## 6. 非機能要件

- **N-01 完全ローカル動作**：一切の外部通信を行わない。法律文書等の機密情報を扱う前提であり、本要件は必須とする。
- **N-02 配布形態**：PyInstallerによる単一exe（onefile方式）。インストール作業を要しない。
- **N-03 起動・実行環境**：Windows 10 / 11（64bit）。追加ランタイムのインストールを不要とする。
- **N-04 性能目安**：A4・20ページ程度のPDFを一般的な事務用PCで1分以内に変換完了すること（目標値）。
- **N-05 配布時の案内事項**：VBAアセット掲載ページに以下を明記する。
  1. onefile方式のため起動に数秒を要すること
  2. 未署名exeのためWindows SmartScreen警告が表示され得ること、およびその回避手順
  3. グレースケール出力は未確認事項を含むため初回テスト送信を推奨すること
- **N-07 命名規定**：ツールの正式名称（表示名）は「VA FAX」とし、GUIウィンドウタイトル・VBAアセット掲載名・README表記に用いる。フォルダ名・実行ファイル名・%APPDATA%配下のフォルダ名には空白を用いず「VA_FAX」（実行ファイルは VA_FAX.exe）とする。
- **N-06 守秘設計原則**：法律事務所での利用を前提とし、以下を設計原則とする。
  1. 文書内容（ページ画像・テキスト）および文書を特定し得るメタデータ（ファイル名・パス）を、ツールの管理領域（%APPDATA%等）に保存しない。文書に紐づく記録（変換レポート）は利用者自身の案件フォルダ内にのみ置く。
  2. 変換処理の中間データ（ラスタライズ後のページ画像等）はメモリ内処理を原則とし、ディスクへの一時ファイル書き出しを行わない。ファイル名がユーザーの機密情報を含み得ることに鑑み、ディスク上への痕跡残存を構造的に防ぐ。

## 8. 処理フロー

```
[入力PDF選択]
    ↓
[事前診断] … ページ数・用紙サイズ・色・テキスト有無・容量を判定し表示
    ↓          チェックボックス／圧縮方式の初期値を自動提案

    ↓
[変換して出力]
    ├─ 検証：暗号化・破損 → エラー停止（F-20）
    ├─ 検証：ページ数上限超過（プロファイルに上限がある場合）→ エラー停止（F-14）

[ページごとの処理ループ]
    ├─ ラスタライズ（200dpi）
    ├─ 用紙正規化（プロファイル対応外サイズのみ中央配置。大は縮小・小は原寸維持・横向きは回転）

    ↓
[PDF再構成] → [容量判定]
    ├─ 上限以下（プロファイル値）→ 完了
    └─ 上限超過 → 最大サイズのページから順に当該ページのみ
                  dpi／JPEG品質を低減して再計測（F-13）
                  → 全ページ下限到達でも超過ならエラー案内
    ↓
[完了表示・出力フォルダを開く]
```

### 9.1 開発中に実施する事項（ローカルで実施可能）——**実施済み（2026-07-29完了）**

2. **F-09自動方式判定の検証**：✔ 完了。同梱の全合成サンプル13件・計30ページで、文字ページ→単純閾値、写真ページ→誤差拡散、混在文書はページ単位の振り分け、淡色罫線ページ→誤差拡散（色検出経由）となることを確認。実サンプルでも、淡色罫線を含む銀行帳票（誤差拡散が正しく選択され、罫線消失バグの修正を確認）およびスキャン戸籍謄本（単純閾値が正しく選択され、地色は白に飛び容量も上限の約4%に収まる）で適切に動作した。実サンプル自体はリポジトリに含めず、検証に用いた特徴は合成サンプル（sample08・sample12等）として再現してある。

### 9.2 公開後に利用者フィードバック等により確認する事項（運用課題）

以下は本ツールの開発者が実環境を持たないため公開前の確認が実質的に不可能な事項である。ただし、本仕様は確認によってではなく設計によってこの不確実性を処理している（デフォルトは最保守形式の1bit白黒・G4、未確認値は「参考」区分としてUI注記、初回テスト送信の推奨をREADMEに明記）ため、未確認のまま公開して差し支えない。公開後、VBAアセット掲載ページ・支援者向けメール等で利用者からのフィードバックを募り、確認が取れ次第プロファイル定義・注記・掲載文を更新する（F-27の外部JSON構造により、プロファイル更新はexeの再ビルドなしに配布できる）。

1. **グレースケール受理可否（MOT/FAX）**：確認が取れるまでグレースケールは注記付きオプションに留める。
2. **テキスト付きPDF送信失敗の再現**：確認が取れるまで、掲載文の訴求文言は断定を避けた表現とする。
3. **eFax・jFaxの容量上限（合計1MB）の公式裏付け**：確認が取れ次第「参考」から「検証済」へ格上げし、UI注記を解除する。
4. **03FAX・faximoの公表仕様**：仕様表が確認でき次第、同梱プロファイルに追加する。

## 10. 対象外事項（本版のスコープ外）

1. Word・Excel・画像等、PDF以外の形式からの直接変換
2. 複数ファイルの一括処理
3. FAX送信操作そのもの（各サービスへのアップロード・送信は利用者が当該サービス側で行う）
4. TIFF形式での出力（PDF出力のみとする。必要性が確認された場合にv2で検討）
5. 変換履歴CSV（全案件のファイル名をツール管理領域に一元蓄積する構造が守秘設計原則N-06に反するため見送り）
6. 公表仕様を確認できていないサービスの同梱プロファイル（03FAX・faximo等。仕様表の確認が取れ次第v1.xで追加。当面はカスタムプロファイルで対応）
7. macOS対応（主要対象環境をWindowsとするため。標準プロファイルのMOT/FAXもMac非対応である）
