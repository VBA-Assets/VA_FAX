**【2026-11-17改訂（第1.50版・Ver200）：方針の転換】** Ver130 までは「入力のPDFを変換して、別のファイルに出力する」ツールだった。Ver200 から、VA mints Ver300 と同じ方針（2026-11-17 班長決定）により、FAXで送るPDFの準備を、このツールだけで済ませられるようにする。主な変更は次のとおり。①通常のPDF編集アプリと同じく、ファイルを開く・コピーして開く・保存・名前を付けて保存の形にする（出力先・出力ファイル名の設定、［変換して出力］、入力ファイルの一覧はなくす。F-32）。②ページの追加・削除・並べ替え・回転と、元に戻す・やり直すを設ける（F-33）。③画像（JPEG・PNG）をページとして取り込めるようにする（F-34）。④圧縮方式と容量超過時の処理方式に「何もしない」を加える（F-11・F-13）。⑤変換レポートをなくす（旧F-25）。⑥配るものに入れる部品を MIT License と両立するものだけにし、img2pdf（LGPL-3.0）を外す（N-08）。⑦ウィンドウの大きさ・位置を保存する（F-23）。これに伴い、「入力ファイルは変更しない」（旧F-03）を改めた（［保存］は、開いたファイルを書き換える）。本文中に残る「入力ファイル」「出力」等の語は、Ver200 では「開いたファイル・追加したファイル」「保存」と読み替える箇所がないよう、各要件を書き改めた。

## 1. 背景と目的

### 1.1 背景

インターネットFAXサービスは、PDF等のファイルをアップロードしてFAX送信を行うが、送信可能なファイルにはサービスごとに公表仕様上の制約がある（例：MOT/FAX〔バルテック〕はPDF/TIFF・最大3MB・A4のみ・カラー未対応、eFaxは合計1MBまで、メッセージプラスは1ファイル5MBまで等）。法律事務所等の利用現場では、Word等で作成した文書やスキャンした資料をこれらの制約に適合させるために相当な手作業が発生していると推察される（実際、eFax利用者には容量制限のため50枚の資料を分割送信した例が報告されている）。

また、テキストデータを含むPDF（Word等から直接出力したPDF）は、FAXサービスのサーバー側で行われるフォント再レンダリング処理に起因して、フォント置換や送信失敗が発生する場合があると考えられる（MOT/FAXの公表注記等。第4.3章参照）。全ページをラスタライズする本ツールの方式は、サービスを問わずこの種の問題を回避する。

### 1.2 目的

インターネットFAXにアップロードするPDFファイルの準備作業を省力化するWindows用デスクトップツールを開発し、VBAアセットで公開することにより、法律事務所をはじめとするFAX利用事業所のIT化を推進する。送信制約の数値はインターネットFAXサービスごとに異なるため、制約値は「サービスプロファイル」として切替可能な構造とする（第5.9章）。第一版で検証対象とする標準プロファイルはMOT/FAX（バルテック）である。**【2026-11-17改訂（Ver200）】** 準備作業（ページの追加・削除・並べ替え・回転、送信用の形式への変換、保存）を、ほかのPDF編集アプリを使わずに、このツールだけで済ませられるようにする。

### 1.3 ツールの中核価値

1. 任意のPDFを、選択したインターネットFAXサービスの制約に適合する形式（標準プロファイルのMOT/FAXでは A4・モノクロ・3MB以内の画像PDF）に自動変換する。
2. 全ページをラスタライズ（画像化）することで、テキストデータ付きPDFのフォント問題・送信失敗リスクを構造的に排除する。
3. Python実行環境を持たない事務職員が、ダウンロード後すぐに使える形（単一exe）で提供する。
4. 送信票と本文の組み合わせ、要らないページの削除、向きの違うページの回転など、送信の前に要るページの編集を、同じ画面で行える（Ver200）。

## 4. 標準プロファイル（MOT/FAX）の送信仕様

### 4.1 公式仕様（一次資料により確認済み）

出典：バルテック MOT/TEL公式サイト 機能ページ（https://www.mot-net.com/mottel/fax ）

| 項目 | 仕様 |
|---|---|
| 対応ファイル形式（送信） | PDF、TIFF |
| ファイルサイズ | 最大3MBまで |
| 対応サイズ（送信） | A4のみ |
| カラー対応 | 送受信ともカラーFAX未対応 |
| 同時送信 | 1送信 |
| 備考 | 「相手に送られる文字フォントが変わる場合があります」との注記あり |

### 4.2 本ツールが採用する出力仕様

上記制約を確実に満たすため、標準プロファイル（MOT/FAX）における出力仕様を以下のとおり定める。容量上限・用紙サイズ等の数値は選択中のサービスプロファイルにより変わる（第5.9章。以下の各要件における「3MB」「A4」等の記載は、標準プロファイルの値の例示である）。圧縮方式に「何もしない」（F-11）を選んだときは、ページを画像にしないので、下表の形式・色・圧縮・解像度は当てはまらない。

| 項目 | 出力仕様 | 根拠 |
|---|---|---|
| 形式 | PDF（画像のみ・テキストデータなし） | 公式対応形式。ラスタライズによりフォント問題を排除 |
| 用紙サイズ | A4（210×297mm）縦置き | 公式対応サイズ |
| 解像度 | 200dpi（初期値。容量超過時に段階的に低減） | G3 FAXファインモード相当 |
| 色 | 1bit白黒（デフォルト）または8bitグレースケール（オプション） | カラー未対応制約。グレースケールは4.3参照 |
| 圧縮 | 二値化時：CCITT G4／グレースケール時：JPEG | 各色深度で最も容量効率が高い方式 |
| ファイルサイズ | 3MB以下（超過時は自動的に対処） | 公式上限 |

### 4.3 未確認事項（設計上の扱い）

以下はバルテックの公開資料で確認できておらず、確定情報ではない。

1. **グレースケールPDFの受理可否**：業界一般にはFAX送信サービスへのグレースケール入稿は標準的な運用だが、MOT/FAX固有の裏付けはない。→ デフォルトを1bit白黒（確実に受理される最も保守的な形式）とし、グレースケールはテスト送信推奨の注記付きオプションとする。
2. **テキストデータ付きPDFの送信可否**：送信失敗するとの利用経験の記憶があるが、一次資料の裏付けはない。→ 本ツールは常に画像PDFを出力するため、真偽にかかわらず問題を回避できる。
3. **ページ数上限・暗号化PDFの扱い・対応PDFバージョン**：公開資料に記載なし。→ 暗号化PDFは処理対象外としてエラー扱い（第6.6章）。

## 5. 機能要件

### 5.1 文書とその保存（F-01〜F-03）

- **F-01 文書**：本ツールが一度に扱うのは1つの文書とする。文書は、開いたファイル（F-32）のページと、追加したファイル（PDF・JPEG・PNG。F-33・F-34）のページを、利用者が並べたものである。文書の中身は「ページの表」（どのファイルの何ページ目を、どの向きで、どの順に並べるか）としてメモリ内に持ち、ページの編集（F-33）はこの表を書き換えるだけとする（材料のファイルの内容は、開いた・追加した時点でメモリに読み込む。N-06）。ページ数・件数の上限は設けない（実質的な上限は、選択中プロファイルのページ数・容量の制約〔F-13・F-14〕が担う）。保存されるのは1送信分の1つのファイルであり、複数のファイルをそれぞれ別のFAXへ変換する一括処理（フォルダ一括処理）は行わない。暗号化・破損したファイルは開かず・追加せず、どのファイルが原因かを明示してエラー表示する（F-20・F-21。ログにはファイル名を記録しない〔F-24〕）。
- **F-02 保存**：［保存］［名前を付けて保存］（F-32）は、ページの表のとおりにページを並べ、選択中の処理（圧縮方式・用紙正規化・容量超過時の処理方式。F-07〜F-13）を行ったものを、1つのPDFファイルとして書く（容量超過時の処理方式「分割して再実行」で実際に分割が起きた場合を除く。F-13）。出力先のフォルダ・ファイル名の方針の設定（Ver130 までの「入力ファイルと同じフォルダ／固定フォルダ」「入力ファイル名＋『_fax』／入力ファイル名と同一」）は、Ver200 でなくした（2026-11-17 班長指示）。保存先は、通常のPDF編集アプリと同じく、開いたファイルそのもの（［保存］）か、利用者がその場で指定した名前（［名前を付けて保存］）である。
  - 保存は、同じフォルダに一時的な名前で書き終えてから、目的の名前に置き換える（書いている途中で失敗しても、元のファイルを壊さない）。この一時的なファイルは出力そのものであり、N-06 の「中間データ」には当たらない。置き換えに失敗したときは、一時的なファイルを消し、消せなければ名前を示して知らせる。
  - 同じ文書をもう一度保存するときは、前に保存した結果からではなく、材料のページ（メモリ内）から作り直す（変換を重ねて画質を落とさない。処理の選択を変えて保存し直すこともできる）。
  - 二値化・グレースケールで保存したファイルには、本ツールで作ったことを示す印（文書情報の Producer に「VA FAX」）を書く。この印のあるファイルを後で開いたときは、圧縮方式の初めの値を「何もしない」とする（F-06。二重に変換しないため）。
- **F-03 開いたファイルの書き換えと、その確認**：Ver130 までの「入力ファイルは変更しない（非破壊処理）」は、Ver200 で改めた（2026-11-17 班長指示。通常のPDF編集アプリと同じ動きにする）。［保存］は、開いたファイルを書き換える。ただし、次のことを守る。
  - ［保存］（上書き保存）は、押すたびに、上書きしてよいかの確認を出す（「（ファイル名）に上書き保存します。よろしいですか？」。2026-11-17 班長指示。当初の「1つの文書につき1回だけ・中身が変わらないときは出さない」を改めた）。確認の画面には［上書き保存］［名前を付けて保存］［キャンセル］を置く。このツールでは、送信用のファイルを別に作る［名前を付けて保存］を標準の保存とする（F-15・F-32）。
  - 元のファイルを残したい利用者のために、［コピーして開く］（F-32）を設ける。
  - 追加したファイル（ページの材料にしただけのファイル）は、変更しない。［名前を付けて保存］で、追加したファイルと同じ名前を指定したときはエラーとする（材料のファイルを書き換えない）。

### 5.2 事前診断（F-04〜F-06）

- **F-04** ファイルを開いたとき、及びページの編集（追加・削除・並べ替え・回転。F-33）の都度、以下を自動判定し、画面に表示する（文書の全体〔ページの表のとおりに並べたもの〕を対象とし、ページ番号も文書の通し番号で表示する）。
  1. 総ページ数（プロファイルにページ数上限がある場合は上限との照合結果も表示）
  2. 各ページの用紙サイズ（選択中プロファイルの対応外サイズのページがある場合はページ番号とサイズを明示。例「8ページ中2ページがB4です（3、5ページ目）」）
  3. カラー／グレースケール／白黒の別（ページ内画像・描画内容から判定）
  4. テキストデータの有無
  5. 文書の大きさ（ページの表のとおりに、変換せずに組み立てたときの大きさ。変換する前の目安であることを併せて表示する）と、材料のファイルの数
- **F-05** 処理オプション（用紙正規化・圧縮方式等）は、事前診断の結果によって自動でON/OFFを切り替えない。既定設定（F-26）の固定値をそのまま画面の初期状態とする（F-06と同じ考え方。用紙正規化は対応サイズに含まれるページには何も作用しないため、常に有効にしておくこと自体に副作用がない。診断結果はユーザーが手動判断する材料として提示するに留める）。用紙正規化を無効にした場合、対応外サイズのページを含む変換はF-14により停止する。
- **F-06** 圧縮方式（二値化／グレースケール）は常に二値化を既定とする。診断結果には、判断材料としてページ別のカラー／グレースケール／白黒の判定を表示する（F-04）が、文書内容による自動推奨は行わない（二値化はG4圧縮との相性がよくFAXで最も一般的な原稿形式である一方、グレースケールは送信時にサービス側で白黒へ自動変換される際に黒つぶれ・白飛びが生じる場合があるため。詳細はprimary-sources.md参照）。写真・図版中心の原稿でグレースケールを用いるかどうかは、診断結果を踏まえてユーザーが判断し選択する。**【Ver200】** ただし、本ツールで二値化・グレースケールにして保存したファイル（F-02 の印のあるもの）だけを材料とする文書を開いたときは、圧縮方式の初めの値を「何もしない」とする（既に送信用の形式になっているものを、二重に変換しないため。利用者は画面で選び直せる）。

### 5.3 変換処理（F-07〜F-13）

- **F-07 ラスタライズ**：圧縮方式が二値化・グレースケールのときは、全ページを200dpi（初期値）でビットマップ化する。出力PDFはテキストデータを一切含まない。入力PDFの文書情報（作成者・タイトル・作成アプリ等のメタデータ）も出力に引き継がない（出力はページ画像から新規に構築するため構造的に引き継がれない。守秘設計の一部として自動テストで保証する）。出力に書く文書情報は、本ツールで作ったことを示す印（Producer。F-02）だけとする。圧縮方式が「何もしない」のときは、ラスタライズを行わない（F-11）。
- **F-08 用紙正規化（プロファイル準拠）**：選択中プロファイルの対応用紙サイズリストに**含まれない**ページのみを、プロファイルが規定する正規化先サイズ（既定はA4 210×297mm）のキャンバスに中央配置する。アスペクト比は維持する。正規化先サイズより**大きい**ページは縮小するが、正規化先サイズより**小さい**ページはあえて拡大しない（原寸のまま中央配置する。文書の実寸を不必要に拡大する必要はないため）。いずれの場合も出力ページ自体は正規化先サイズ（A4等）になる。対応サイズに含まれるページは寸法を変更せずそのまま通す（例：MOVFAXプロファイルではB4・A3ページを縮小しない）。
  - 縮小を伴う場合（B4→A4 約82%、A3→A4 約71%等）は、縮小率と判読性低下の注意を事前診断欄に表示する。
  - サイズ判定には±2mmの許容誤差を設け、対応サイズに実質一致するページに不要な処理を行わない。レターサイズ（215.9×279.4mm）は対応サイズに含まれない限り正規化対象とする。
  - 横向き（ランドスケープ）ページの扱いはプロファイルの横向き受理可否属性に従う。横向き非対応のプロファイル（MOT/FAX等）では90度回転して縦置きに収める（原寸維持。縮小配置方式は採用しない）。横向き対応のプロファイル（MOVFAX等）では回転しない。利用者がページを回転したとき（F-33）は、回転した後の向きを、そのページの向きとして扱う。
- **F-09 二値化（デフォルト圧縮方式）**：グレースケール変換後に1bit白黒化する。ディザ方式は「自動」「誤差拡散」「単純閾値」から選択可能とし、初期値は「自動」とする。
  - **自動選択時は、まずページに色（無彩色でない画素）が含まれるかを判定し、次に輝度ヒストグラムを分析して方式を決定する**。淡い色のみで印刷された罫線・枠等を含むページ（銀行帳票等に見られる、輝度だけでは白背景とほぼ区別できない淡色の線。単純閾値では白と判定され消えてしまう）は、色の存在をもって誤差拡散を適用する。無彩色のページは、文字・線画調（輝度分布が白黒二極に集中）には単純閾値（閾値は大津の判別分析法によりページごとに自動決定）、写真・グラデーション調には誤差拡散ディザを適用する。
  - 本方式の趣旨：スキャン由来のページ（文字が画像として格納され、紙の地色・照明ムラを含む）を誤差拡散でディザリングすると、背景が無数の微細な点に変換されてG4圧縮の効率が崩壊し、ページサイズが著しく膨張する。単純閾値であれば背景は白に飛び、文字は明瞭に残り、サイズも最小となる。送信票と本文を合わせた文書ではWord由来ページとスキャン由来ページの混在が通常であるため、ページ内容に応じた方式選択を既定動作とする。
  - 自動選択で適用した方式は、ページごとに処理ログ（F-17）に記録する。
  - 閾値・パラメータは小さい文字（条文・約款等）が潰れないことを優先して調整する。
  - OCRによるテキスト復元は行わない（認識誤りにより文書の記載内容が変わるリスクがあるため。出力は画像PDFでありサイズ面でも不要）。
- **F-10 グレースケール（オプション圧縮方式）**：8bitグレースケール＋JPEG圧縮で出力する。JPEG品質は「高・中・低」から選択可能とし、初期値は「中」とする。選択時、UI上に「サービス側で黒つぶれ・白飛びが起こる場合があります。実際に送信してご確認ください」との注記を表示する（他社インターネットFAXサービスの公式情報に基づく。primary-sources.md参照）。
- **F-11 圧縮方式は排他選択**：「二値化」「グレースケール」「何もしない」の3つから、ラジオボタンで1つを選ぶ。**「何もしない」（Ver200。2026-11-17 班長指示）** は、ページを画像にせず、材料のページをそのまま写して保存する（文字データ・カラーも残る。ページの回転は PDF の回転の属性で行い、画像〔F-34〕は1ページのPDFにして載せる）。送信用の形式に既になっているファイルのページを入れ替えるだけのとき、及び本ツールをFAXの制約と関わりなくページの編集に使うときのための選択肢である。「何もしない」のときは、用紙正規化（F-08）と、容量超過時の処理方式「解像度・品質を下げて再実行」（F-13）は効かないので、選べない状態にして、その理由を画面に示す。このとき、容量超過時の処理方式に「解像度・品質を下げて再実行」が選ばれていたら、「何もしない」に切り替え、圧縮方式を二値化・グレースケールに戻したときに、元の選択に戻す。プレビューは、材料のページをそのまま（回転だけを行った状態で）表示し、ステータス欄に「そのままの表示（画像にしません）」と示す。また、選択肢の傍に「ページを画像にしません。文字データ・カラーが残り、サービスによっては送信できない場合があります」と注記する（F-16）。
- **F-12 PDF再構成**：二値化時はCCITT G4圧縮、グレースケール時はJPEG圧縮で画像を格納したPDFを生成する。
- **F-13 容量制御（ページ単位の適応制御）**：保存するファイルがプロファイルの容量上限（標準プロファイルでは3MB。本要件内の記載は同値を例とする）を超えた場合、容量超過時の処理方式（「解像度・品質を下げて再実行」〔初期値〕・「分割して再実行」・「何もしない」の3つからラジオボタンで選ぶ。既定値は既定設定〔F-26〕）に従う。Ver130 までは「対処しない、という選択肢は設けない」としていたが、Ver200 で「何もしない」を加えた（2026-11-17 班長指示）。全ページ一律の解像度低減は行わない。
  1. 「解像度・品質を下げて再実行」：ページごとの出力サイズを計測し、容量超過の原因ページ（出力サイズの大きいページ）を特定したうえで削減する。
     1. 削減方式（既定設定〔F-26〕で選択。初期値は「原因ページのみ」）に従い、削減対象を選ぶ。
        - **原因ページのみ**：最もサイズの大きいページから順に、当該ページのみ削減を適用して総容量を再計測する。容量超過の原因でないページの解像度・品質は変更しない（複数のファイルを合わせた文書において、一部の写真・図版ページが原因で文字ページまで劣化させることを防ぐ）。原因が1ページに集中している場合、そのページだけで解像度・品質を大きく下げる必要が生じる場合がある。
        - **全体を均等に**：削減可能な全ページを1段階ずつ均等に削減してから総容量を再計測する。原因ページの下げ幅は緩和されるが、原因でないページも画質が落ちる。
        - いずれの方式でも、二値化時は解像度を段階的に低減（200→150→120dpi）、グレースケール時はJPEG品質を低減し、なお超過時は解像度を低減する。
     2. すべてのページが下限（120dpi）に達してもなお容量上限を下回らない場合はエラーとし、ページ分割等の対応をユーザーに案内する。
  2. **「分割して再実行」**：解像度・品質は落とさず、ページの順序を維持したまま、各ファイルが容量上限に収まる単位で複数のPDFに分割する（重要書類等、画質より完全性を優先したい場合の選択肢）。
     - 出力ファイル名は「（元のファイル名）\_1of3.pdf」のように連番＋総数のサフィックスを付与する。分割が発生しない（全体が既に容量上限以下の）場合は、1つのファイルとして、文書の名前のまま保存する（F-02）。
     - 1ページ単体で容量上限を超える場合（情報量の多いページが単独でも収まらない場合）に限り、そのページのみ「解像度・品質を下げて再実行」と同じ段階的削減を適用する。全段階を尽くしてもそのページ単体で収まらない場合はエラーとする。
     - 保存先に、分割後と同じファイル名（連番サフィックス付き）のファイルが既に存在する場合は、保存を行わずエラーとし、該当ファイルの移動・削除または［名前を付けて保存］を案内する（分割の有無・個数は変換結果が出るまで確定しないため、書き込みの直前に検証する）。分割後のファイル名が、開いたファイル・追加したファイルと一致してしまう場合も、同様にエラーとする（F-03）。
     - 分割ファイル群の書き込みが途中で失敗した場合、書き込み済みの一部のパートだけが残ると利用者が不完全なセットと気づかずに送信する恐れがあるため、当該実行で書き込んだ分は削除する。削除できなかった場合はファイル名を明示して手動削除を案内する。
     - 分割が発生した場合、文書の名前（連番サフィックスのない名前）のファイルには書き込まない。したがって、開いたファイルは変わらず、文書は未保存のままとなる（題名の未保存の印は消さない）。完了のお知らせで、分割してできたファイルの名前と、開いたファイルは変えていないことを示し、［フォルダを開く］ボタンを置く（F-18）。
  3. **「何もしない」（Ver200）**：容量上限を超えていても、そのまま保存する。保存の後のお知らせに、容量（実際の値と上限）と、上限を超えているためこのままでは送信できない見込みであることを示す。
  4. ページごとの最終解像度・品質は処理ログ（F-17）に記録し、どのページにどの削減が適用されたかを利用者が検証できるようにする。
  5. 「解像度・品質を下げて再実行」「分割して再実行」で対処しきれない場合（前者で全ページが下限に達してもなお超過する場合、または後者で1ページ単体が下限まで縮小してもなお超過する場合）は保存を行わずエラーとし、具体的な対処案内（二値化時はディザ方式を「単純閾値」へ切替、グレースケールへの切替、ページの削除〔F-33〕の各提案）を表示する（F-21）。圧縮方式が「何もしない」のときに選べるのは、「分割して再実行」と「何もしない」である（F-11。このときの分割は、1ページ単体が上限を超えるとエラーとする）。

### 5.4 サイズ検証とエラー停止（F-14）

- **F-14 送信可否検証**：圧縮方式が二値化・グレースケールのとき、以下の場合は、保存を行わずエラーで停止する。圧縮方式が「何もしない」のときは、停止せず、保存の後のお知らせに、プロファイルの制約に合っていない点（ページ数・用紙サイズ）を示す（「何もしない」は、利用者が送信用の形式への変換を求めていない選択であるため。F-11）。
  - **ページ数上限検証**：選択中プロファイルにページ数上限がある場合（秒速FAX送信=10ページ、MOVFAX=255ページ等）、文書のページ数が上限を超えるときはエラーとし、ページの削除（F-33）を案内する（Ver130 までは「本ツールはページの削除・分割を行わない」としていたが、Ver200 で改めた）。事前診断（F-04）でも超過を警告表示する。
  - **用紙サイズ検証**：用紙正規化がOFFの状態で、選択中プロファイルの対応外サイズのページを含むPDFの変換を実行しようとした場合、変換を行わずエラーで停止し、「（プロファイル名）の対応外サイズのページが含まれるため送信できません。用紙の正規化を有効にしてください」と表示する。プロファイルの対応外サイズを含むPDFは出力しない。（※本項の主語の変更に伴い、以降の「F-14」への参照はこの送信可否検証全体を指す）

- **F-24 エラー・診断ログ**：`%APPDATA%\VA_FAX\logs\` に日付別のログファイルを保存する。
  - ログには、**入力・出力のファイル名およびパスを一切記録しない**（デバッグモードのような切替も設けず、常時この方針とする）。
  - 記録対象は、処理段階・エラー種別に加え、事前診断結果（総ページ数・各ページの用紙サイズ・カラー/グレースケール/白黒の別・テキストデータ有無・文書の大きさ・暗号化検出の有無）、ページごとの解像度・二値化方式・再試行内容、予期しない例外発生時のスタックトレースとする。これらはファイル名・パス・文書内容そのものではないため、常時記録して差し支えない。
  - 本ツールはVBAアセットで公開され、利用者から問合せがあった際は「ログファイルを送ってください」と案内する運用を想定する。ファイル名を含まない前提のログのみで、事前診断結果とスタックトレースから原因の見当を付けられるようにする。
  - ログの保存件数・期間には上限を設け、自動的に古いものから削除する。
- **F-25（廃止）**：Ver130 までの変換レポート（処理内容の記録を、出力PDFと同じフォルダにテキストファイルで保存するオプション）は、Ver200 でなくした（2026-11-17 班長指示「変換レポートの作成は不要」）。処理の内容は、処理ログ（F-17）で確かめる。
- **F-31 診断情報のコピー**（2026-11-10 班長決定。VA mints・VA Caseシリーズと同じ）：［ヘルプ］→［診断情報をコピー］で、不具合をAI・作成者に相談するときに渡す文をクリップボードへコピーする。
  - 含めてよいのは、ツールの版・環境（OS・Python・Tk・画面の大きさと拡大率）・選択中プロファイルの制約値・変換の既定設定と画面の処理内容の選択の値・文書のページ数・材料のファイルの数・事前診断の結果の要約・起きた例外の型と発生位置（ファイル名・行・関数名）・OSErrorの番号のみとする。
  - **開いた・追加した・保存したファイルの名前、ファイルやフォルダの場所、例外のメッセージの本文、利用者名・PC名は含めない**（F-24と同じ理由。OSError等のメッセージにはファイルのパスが入りうる）。文書は、名前があるか（保存先が決まっているか）だけを示す。
  - 起きた例外は、型と発生位置だけの記録として `%APPDATA%\VA_FAX\errors.json` に保存し（直近30件。表示は新しい10件）、ツールを閉じた後・異常終了した後でも渡せるようにする。記録できない場合も処理は続行する。
  - コピー後に、中身を含まないこと・貼り付けて内容を確認できることを案内するメッセージを表示する。
- **F-26 変換の既定設定**：処理オプションの既定値一式を、［ファイル］→［オプション］の「処理内容の既定値」のタブ（F-35。Ver130 までは設定メニューの「変換の既定設定」画面）で構成できる。設定項目は以下とし、settings.json（F-23）に保存する。既定設定には文書に関する情報を一切含めない。
  1. 圧縮方式の既定値：「二値化（白黒・G4圧縮）」（初期値）／「グレースケール（JPEG圧縮）」／「何もしない」（F-06により、文書内容による自動判定は行わない。実際に使用する圧縮方式（G4／JPEG）を選択肢の表記に明示し、分かりやすくする）
  2. 用紙正規化を初期状態で有効にするかどうか（チェックボックス。初期値ON。F-05により、診断結果による上書きは行わない）
  3. ディザ方式（F-09）・JPEG品質（F-10）・容量超過時の処理方式「解像度・品質を下げて再実行」（初期値。削減方式「原因ページのみ」〔初期値〕／「全体を均等に」を含む）／「分割して再実行」／「何もしない」（F-13）の各既定値
  - 出力先方針・出力ファイル名方針（Ver130 までの項目1）と、変換レポート保存の既定値は、Ver200 でなくした（F-02・旧F-25）。Ver130 までの settings.json にこれらの項目が残っていても、読み飛ばす（エラーにしない）。
  - 圧縮方式・用紙正規化・容量超過時の処理方式の各項目は、選択肢の表記および配置（圧縮方式は各選択肢の直下に詳細設定〔ディザ方式／JPEG品質〕を表示する等）をメイン画面の処理内容選択欄と同一とする（「既定値」の設定であることが文言からも明確になるよう、「常に」等の付加的な修飾語は付けない）。ただし、各選択肢の副作用を説明する「※」注記（F-15参照）は、既定値を設定するだけの本画面では判断材料として不要なため表示しない。
  - 画面上での手動変更はその文書限りとし、次にファイルを開いたときに既定設定から再計算する。処理オプションの前回値の無条件自動引き継ぎは行わない（共有PCでの前任者設定の意図しない引き継ぎを防ぐ）。
  - 複数PCへの標準設定配布は settings.json のコピーによる（F-23・F-28）。名前付きプリセットの保存・呼び出し、およびエクスポート／インポート機能は設けない。

### 5.9 サービスプロファイル（F-27〜F-29）

- **F-27 プロファイル定義**：インターネットFAXサービスごとの送信制約（サービス名・最大ファイルサイズ・対応用紙サイズリストと正規化先・横向き受理可否・ページ数上限・カラー可否・解像度の初期値と下限・対応出力形式・利用者向け注記文言・確認状態〔検証済／参考〕と出典）を、コードから分離した外部定義（JSON）として持つ。プロファイル定義はexeに同梱するほか、`%APPDATA%\VA_FAX\profiles\` に追加配置されたプロファイルを読み込むことで、exeの再ビルドなしにサービスを追加できる構造とする。プロファイルには文書に関する情報を含めない（N-06に整合）。
- **F-28 プロファイル選択（初回選択・固定方式）**：1つの事務所が使用するインターネットFAXサービスは通常1つであることを前提に、プロファイルは初回に選択して固定する方式とする。
  - **初回起動時のみ**、プロファイル選択画面（「お使いのFAXサービスを選んでください」）を表示する。選択結果は settings.json に保存する。
  - **通常画面にプロファイル選択UIは表示しない**。画面には選択中のプロファイル名と主要制約値（例「対象サービス：MOT/FAX（上限3MB・A4）」）を表示するのみとし、事務職員の日常操作は「ファイル選択→変換実行」に限られるようにする。誤操作による意図しないプロファイル切替を構造的に防ぐ。
  - サービス変更（乗り換え等の稀な場合）は、［ファイル］→［オプション］の「FAXサービス」のタブ（F-35）からのみ行える。ほかのサービスからカスタムに替えるときは、保存の前にカスタムの内容の入力を挟む（入力を取りやめたら保存しない）。カスタムを選んでいる間は、タブの［カスタムの内容を入力...］で内容を変えられる。
  - settings.json のプロファイル指定項目は手動編集にも耐える平易な構造とし、項目仕様をREADMEに記載する。これにより、管理者が設定済み settings.json を事務所内の複数PCへ配布してプロファイルを固定する運用（実質的な設定ファイル配布方式）を可能とする。
  - 同梱プロファイルは以下の7つとする（各制約値の出典・確認日は docs/primary-sources.md に記録）。
  1. **MOT/FAX（標準・検証対象）**：本書第4.1章の公表仕様に基づく。PDF・最大3MB・A4のみ・モノクロ。
  2. **MOVFAX（公式仕様確認済）**：日本テレネット公式FAQの仕様表に基づく。PDF推奨・最大10MB・255ページ上限・A4/B4/A3（縦横どちらも対応）・画質はファインモード固定（200×200dpi）。
  3. **メッセージプラス（公式仕様確認済）**：公式FAQ・機能ページに基づく。PDF等・1ファイル5MBまで・用紙はサービス側でA4/B4に自動調整（ツール側の用紙検証は緩和）。印刷不許可・パスワード付きPDFは送信不可（本ツールの出力は制限なしPDFのため適合）。
  4. **eFax（参考・二次情報ベース）**：公式ヘルプで確認できるのは添付最大5件・パスワード付き不可・対応形式一覧まで。容量上限「合計1MB」は送信画面の表示文言を引用した複数の二次情報および実利用者の証言に基づく参考値であり、公式ウェブ文書では未確認。プロファイル選択時、UI上にこの旨の注記を表示する。本ツールの出力は単一PDFのため、出力1ファイルを1MB以内に収める制約として扱う。
  5. **秒速FAX送信（公式仕様確認済）**：Toones（Karigo）公式サイトに基づく。原則PDF（Word・Excel・画像は再現性が低く非推奨）・容量合計1MB以下・10ページ以内・A4サイズ標準。eFaxと並ぶ厳しい容量制限を公式に明記しているサービスであり、本ツールの容量制御の実益が大きい。
  6. **jFax（参考・容量は推定）**：eFaxの姉妹サービス（同じConsensus社）。送信可能ファイル形式一覧は公式ヘルプで確認済み（eFaxの公表表と同一）。容量上限は公式に記載がなく、同一インフラであることからeFaxと同じ「合計1MB」と推定した参考値とする。プロファイル選択時、UI上にこの旨の注記を表示する。
  7. **カスタム**：利用者が自身の契約サービスの公表仕様（容量上限・対応用紙等）を手動入力して使用する。プロファイル選択画面でカスタムを選び「決定」すると入力フォームを表示する。「お使いのサービスの公表仕様をご確認のうえ入力してください」との案内とともに、サービス名・最大ファイルサイズ（MB）・ページ数上限（空欄可）・対応用紙サイズ（A4・B4・A3・A5・レターから複数選択）・横向き受理可否・カラー対応等の備考を入力できる。解像度段階・JPEG品質段階・正規化先サイズ（A4）は他プロファイルと共通の既定値を用い、編集対象としない（複雑さを抑えるため）。入力値はプロファイルとして `%APPDATA%\VA_FAX\profiles\` に保存する（F-27の追加プロファイル配置方式により、当該JSONファイルのコピーで他のPCでも利用できる）。既にカスタムを選択中の状態で再度この画面を開いた場合も、入力内容を更新できる。
- **F-29 制約値のハードコード禁止**：容量判定（F-13）・用紙検証（F-08・F-14）・カラー処理（F-09〜F-11）・エラーメッセージ等、制約に依存するすべての処理は、選択中プロファイルの値を参照して動作する。「3MB」「A4」等の数値をコードに直接埋め込んではならない。
- 補足：実在サービス名を冠したプロファイルの同梱は、当該サービスの公表仕様（一次資料）を確認できたもの、または出典の性質を注記した参考プロファイル（eFax）に限る。各プロファイルの制約値はいずれも公表仕様に基づくものであり、実送信による動作検証は行っていない旨（MOT/FAXを含む。第9.2章の運用課題）を、README・操作マニュアル・VBAアセット掲載文に明記し、あわせて全サービス共通で初回のテスト送信を推奨する。

### 5.10 ページプレビュー（F-30）

- **F-30 プレビュー表示**：画面左側にプレビュー欄を表示する。文書の全体（ページの表のとおりに並べたもの）を表示対象とし、ページの編集（F-33）の都度更新する（F-04と同期）。
  1. 全ページのサムネイル一覧を表示し、任意のページを選択すると同欄内に拡大表示する。サムネイル一覧は、ページの一覧（F-15）を兼ね、ページの選択・並べ替え・削除（F-33）をここで行う。各サムネイルの下にページ番号を表示する。
  2. プレビューは選択中の処理内容（圧縮方式・ディザ方式・用紙正規化）を反映した状態で表示し、処理内容の変更時に自動的に再生成する（この表示をステータス欄に「変換イメージ」と常時明示する）。拡大表示は本変換と同じ解像度（選択中プロファイルの既定dpi）で変換パイプラインを実行し、表示時にのみ画面サイズへ縮小する（低解像度で処理すると、二値化閾値の自動算出・ディザ方式の自動判定等の結果が本変換と食い違いうるため。表示時の縮小は完成した結果画像のズームであり判定には影響しない）。圧縮方式が「何もしない」のときは、材料のページをそのまま（回転だけを行った状態で）表示する。
  3. サムネイル・拡大表示の生成は表示範囲に応じた遅延読み込みとし、バックグラウンドスレッドで行いGUIの操作をブロックしない。
  4. プレビュー欄は他の画面領域との境界をドラッグして幅を変更できる（リサイズ可能）。
  5. PageUp／PageDownキーで前後のページへ、Home／Endキーで先頭・末尾ページへ、選択を移す（Shift併用で選択の範囲を広げる。キー操作は、サムネイルのクリック等でプレビュー欄を操作した後に有効となる）。拡大表示欄の上でのマウスホイール操作でも前後のページへ切り替えられる（サムネイル一覧側のホイールは一覧のスクロールに用いる。ホイール操作はフォーカス位置に依らず常時有効）。
  6. **保存の後は、シミュレーションではなく実際に保存したPDFそのものをプレビュー欄に表示する**（ステータス欄の表示を「変換イメージ」から「保存した結果」に切り替えて常時明示する）。これにより、容量超過時の処理方式（F-13）による解像度・品質の低下を含む最終の内容を、ファイルを別のアプリで開かずに確認できる。「分割して再実行」により複数ファイルに分かれた場合は、最初のファイルのみを表示する（他のファイルは、完了のお知らせの［フォルダを開く］から確認する）。処理内容の選択を変えたとき、ページを編集したときは、材料のページからのシミュレーション表示（変換イメージ）に戻る（文書のページの表は、保存の後も材料のページを指したままである。F-02）。
  7. 保存する前のプレビューにおける残余の差異：サムネイル一覧はページ探し用の簡易表示であり低解像度で生成する（内容確認は拡大表示側で行う）。また、容量超過時の処理方式による調整結果（解像度低減の程度、実際に何ファイルに分割されるか等）、およびグレースケール時のJPEG品質は、保存する前のプレビューには反映されない（全ページ処理後でないと確定しないため。いずれも保存の後の実物表示〔前項〕で確認できる）。

### 5.11 ファイルの操作とページの編集（F-32〜F-34）

Ver200 で設けた（2026-11-17 班長指示「通常のPDF編集アプリと同じように、ファイルを開く、コピーして開く、保存、名前を変えて保存ができるようにする」「ページの追加もできるようにする」）。

- **F-32 ファイルの操作**：リボンの「ファイル」の組と、メニューの［ファイル］に、次の操作を置く。
  1. **開く**（Ctrl+O）：PDFファイルを1つ選んで開く。開いたファイルが、その文書の保存先になる。ウィンドウへのドラッグ＆ドロップでも開ける（文書を開いていないとき。複数のファイルを落としたときは、1つ目を開き、残りをその後ろに追加する〔F-33〕。文書を開いているときのドロップは、ページの追加とする）。画像（JPEG・PNG）を選んだ・落としたときは、［コピーして開く］と同じ扱いとする（画像のファイルをPDFで書き換えないため。名前の初めの値は「元の名前.pdf」）。
  2. **コピーして開く**：PDFファイルを1つ選び、その中身を、名前のない新しい文書として開く（元のファイルは保存先にしない）。最初の［保存］では［名前を付けて保存］のダイアログを出す（名前の初めの値は、4のとおり）。元のファイルを残したまま、送信用のファイルを別に作るための操作である。
  3. **保存**（Ctrl+S。上書き保存。リボンでは小さいボタン）：文書を、保存先のファイルに書く（F-02。押すたびに確認を出す。F-03）。名前のない文書では、［名前を付けて保存］と同じ動きとする。文書を開いていないときは押せない。
  4. **名前を付けて保存**（Ctrl+Shift+S。このツールの標準の保存とし、リボンでは大きいボタンにする。2026-11-17 班長指示）：保存のダイアログで場所と名前を指定して書く。ダイアログの名前の初めの値は、開いたファイル（保存した後は、保存したファイル）の名前に「_fax」を付けたもの（例：契約書.pdf → 契約書_fax.pdf。拡張子は .pdf。既に付ける文字で終わる名前には重ねて付けない）、場所の初めの値はそのファイルのフォルダとする。付けるかどうかと、付ける文字は、［ファイル］→［オプション］で選べる（F-35。2026-11-17 班長指示）。［コピーして開く］で開いた文書・画像を開いた文書の名前（題名）にも、同じ規則を使う。以後、指定したファイルが、その文書の保存先になる。既にあるファイルを指定したときは、ダイアログの上書きの確認による。開いたファイル・追加したファイルと同じ名前の扱いは、F-03による。
  5. **閉じる**・**別のファイルを開く**・**ツールの終了**：文書が未保存（題名に未保存の印がある）のときは、「変更を保存しますか？」（保存する／保存しない／キャンセル）を尋ねる。
  - 保存している間は、進捗バーを動かし（F-15）、ファイルの操作・ページの編集のボタンを押せない状態にする。保存は、画面を止めないよう裏で行う。
  - 開いたファイル・追加したファイルの名前と場所は、メモリ内にだけ持ち、設定ファイル・ログ・診断情報に書かない（N-06・F-24・F-31。「最近使ったファイル」の一覧は設けない）。
- **F-33 ページの編集**：リボンの「ページ」の組と、ページの一覧（サムネイル。F-30）、及びサムネイルの右クリックメニューで、次の操作を行う。いずれも、ページの表（F-01）を書き換えるだけで、［保存］するまでファイルには何も書かない。
  1. **追加**：PDF・JPEG・PNGのファイル（複数選択可）を選び、そのページを、選択中のページの後ろ（何も選択していないときは末尾）に入れる。ドラッグ＆ドロップでは、落とした位置（サムネイルの間。挿入位置を線で示す）に入れる。追加したページは選択状態にする。一度の操作で多数件（10件超。サービス制約値ではないUI上の設計値）を追加するときは、「◯件のファイルを追加します。よろしいですか？」の確認を挟む（フォルダ内の大量のファイルを誤ってまとめて落とした場合等の歯止め）。
  2. **選択**：サムネイルのクリックでそのページを選択する。複数ページはShift+クリック（範囲）・Ctrl+クリック（1ページずつ）、全ページはCtrl+Aで選択する。選択中のページは、反転した枠で示す。
  3. **削除**：選択中のページを、リボンの［削除］またはDeleteキーで文書から取り除く（材料のファイルは変えない）。すべてのページを取り除くことはできない（最後の1ページは削除できない旨を説明書きに示す）。
  4. **並べ替え**：サムネイルを押してそのまま動かすと、そのページ（複数ページを選択している状態でその範囲内を押した場合は、選択中のページ全体）が移動する。挿入位置は、サムネイルの間の線（アクセント色）で示し、ポインタが欄の上端・下端にある間は一覧を自動スクロールする。欄の外へ持ち出して放した場合は、選択中のページを削除する（持ち出している間は、マウスカーソルを「矢印＋ゴミ箱」〔同梱のresources/trash.cur〕に変える。枠の縁から余裕〔16px〕を越えた場合のみ「外」と判定する）。ドラッグ中のEscapeキーで、その操作を取りやめる。
  5. **回転**：選択中のページを、左に90°・右に90°・180°回す（リボンの［回転］を押して開くメニュー、又は右クリックメニューで角度を選ぶ）。回した結果は、プレビューにすぐ反映する。二値化・グレースケールでは、回した向きのページを画像にする。「何もしない」では、PDFの回転の属性だけを変える（ページの内容は変えない）。
  6. **元に戻す**（Ctrl+Z）・**やり直す**（Ctrl+Y）：ページの編集（追加・削除・並べ替え・回転）を、1つずつ戻し、また進める。履歴は、文書を開いている間、保存の後も保つ（文書を閉じたときに捨てる）。処理の選択（圧縮方式など）の変更は、履歴の対象にしない。
  7. **右クリックメニュー**（2026-11-17 班長指示）：サムネイルを右クリックすると、ページの各コマンド（追加・削除・左に90°回転・右に90°回転・180°回転・元に戻す・やり直す）のメニューを、ポインタの位置に出す。選択していないページの上で右クリックしたときは、そのページだけを選択してからメニューを出す（選択中のページの上なら、選択を保つ）。一覧の余白の右クリックでは、選択を変えずにメニューを出す。各項目の押せる・押せないは、リボンのボタンと同じとする。
  - ページの編集の都度、事前診断（F-04）とプレビュー（F-30）を更新する。
  - 行わないこと：ページの中身の編集（文字・図の書き込み、注釈、墨消し、切り抜き）、ページの抜き出し保存（文書の一部だけを別のファイルにすること。要るときは、要らないページを削除して［名前を付けて保存］する）。
- **F-34 画像の取り込み**：JPEG・PNGの画像を、1つの画像につき1ページとして、文書に入れられる（F-32の開く・F-33の追加）。
  - ページの大きさは、画像に解像度の情報（dpi）があり、その実寸がプロファイルの正規化先の用紙（既定はA4。画像の縦横に合わせて、縦置き・横置きを選ぶ）に収まるときは、その実寸とする。解像度の情報がないとき、及び実寸が用紙に収まらないとき（72dpi と記録された大きい写真など）は、用紙に、縦横比を保って収まる最大の大きさとする。その後の扱い（用紙正規化・回転・二値化など）は、PDFのページと同じとする。
  - 画像の向きの情報（Exif の Orientation）があれば、その向きに直して取り込む。
  - 圧縮方式が「何もしない」のときは、JPEGは再圧縮せずにそのまま載せ、PNGは画質を損なわない形で載せる。画像の位置情報等のメタデータ（Exif等）は、保存するPDFに載せない。
  - 取り込みはメモリ内で行い、一時ファイルを作らない（N-06）。
- **F-35 オプション**（Ver200。2026-11-17 班長指示）：［ファイル］→［オプション］で、ツールの設定をまとめて選ぶ画面を開く。選んだ値は、［保存］を押したときに settings.json に保存する（F-23。文書に関する情報は含めない。［キャンセル］では何も変えない）。保存の処理の途中は開けない。画面は次の3つのタブとする（Ver130 までの［設定］メニューの「FAXサービスを変更」「変換の既定設定」は、ここにまとめた）。
  1. **保存**：
     - 「［名前を付けて保存］・［コピーして開く］のファイル名に、次の文字を付ける」（チェックボックス。初期値はオン）と、付ける文字の入力欄（初期値は「_fax」）。オンのときは、［名前を付けて保存］のダイアログの名前の初めの値と、［コピーして開く］で開いた文書（画像を開いた文書を含む）の名前に、この文字を付ける（F-32）。オフのときは、開いたファイルと同じ名前（拡張子は .pdf）とする。付ける文字は、前後の空白を除いて20文字まで、ファイル名に使えない文字（\ / : * ? " < > |）と制御文字は使えない。使えない文字・空欄のまま［保存］を押したときは、エラーを示して「保存」のタブを表示する。設定ファイルに使えない値が書かれていたときは「_fax」とする。
     - 「保存の後に、保存したフォルダを開く」（チェックボックス。初期値はオフ）：オンのときは、保存の後（分割したときを含む）に、保存したフォルダをエクスプローラー等で開く（FAXサービスの画面へアップロードするときに、ファイルを探す手間を減らす）。分割の完了のお知らせには、このとき［フォルダを開く］ボタンを置かない。
  2. **処理内容の既定値**：F-26 の項目（メイン画面の処理内容の選択欄と同じ並び・文言）。値を変えて保存したときは、開いている文書の画面の処理内容も、新しい既定値に戻す（変えていなければ、画面の選択はそのまま）。
  3. **FAXサービス**：F-28 のプロファイルの選択（初回起動時の選択画面と同じ並び）と、［カスタムの内容を入力...］。変えて保存したときは、開いている文書を新しいサービスで診断し直す。

## 6. 非機能要件

- **N-01 完全ローカル動作**：一切の外部通信を行わない。法律文書等の機密情報を扱う前提であり、本要件は必須とする。
- **N-02 配布形態**：PyInstallerによる単一exe（onefile方式）。インストール作業を要しない。
- **N-03 起動・実行環境**：Windows 10 / 11（64bit）。追加ランタイムのインストールを不要とする。macOSは、利用者がPython 3（Tkを含むもの）と依存ライブラリ（requirements.txt）を入れ、ソースから動かす場合に限り対象とする（exe等の実行ファイルは配らず、動作は保証しない。2026-10-25 班長決定）。Windows以外では、設定・追加プロファイル・ログの置き場所を `%APPDATA%\VA_FAX` に代えてホームの `.va_fax` とする。標準プロファイルのMOT/FAXはMacから利用できない（バルテック公式サイトの利用可能機器にMacを含まない。primary-sources.md）ため、Macでは他のサービスのプロファイルを選ぶことになる旨をREADMEに明記する。
- **N-04 性能目安**：A4・20ページ程度のPDFを一般的な事務用PCで1分以内に変換完了すること（目標値）。
- **N-05 配布時の案内事項**：VBAアセット掲載ページに以下を明記する。
  1. onefile方式のため起動に数秒を要すること
  2. 未署名exeのためWindows SmartScreen警告が表示され得ること、およびその回避手順
  3. グレースケール出力は未確認事項を含むため初回テスト送信を推奨すること
- **N-07 命名規定**：ツールの正式名称（表示名）は「VA FAX」とし、GUIウィンドウタイトル・VBAアセット掲載名・README表記に用いる。フォルダ名・実行ファイル名・%APPDATA%配下のフォルダ名には空白を用いず「VA_FAX」（実行ファイルは VA_FAX.exe）とする。
- **N-06 守秘設計原則**：法律事務所での利用を前提とし、以下を設計原則とする。
  1. 文書内容（ページ画像・テキスト）および文書を特定し得るメタデータ（ファイル名・パス）を、ツールの管理領域（%APPDATA%等）に保存しない。本ツールが文書について書き出すのは、利用者が保存したファイルだけとする（Ver130 までの変換レポートは、Ver200 でなくした）。
  2. 変換処理の中間データ（ラスタライズ後のページ画像等）はメモリ内処理を原則とし、ディスクへの一時ファイル書き出しを行わない。ファイル名がユーザーの機密情報を含み得ることに鑑み、ディスク上への痕跡残存を構造的に防ぐ。
- **N-08 部品のライセンス**（Ver200。2026-11-17 班長決定。VA mints Ver300 と同じ）：配るもの（exe）に入れる部品は、MIT License と両立するもの（MIT・BSD・Apache・MPL・PSF など）だけとする。GPL・AGPL・LGPL の部品は入れない。
  - Ver130 まで使っていた img2pdf（LGPL-3.0）は外し、画像PDFの組み立て（F-12）は、pypdf と Pillow で自前で行う（2026-11-17 に試作で確かめた。同梱サンプル12件・二値化とグレースケール・200dpiと150dpiの計48通りで、img2pdf の出力と1画素も違わず、大きさは約700バイト小さい）。img2pdf が使っていた pikepdf・lxml も、あわせて入らなくなる。
  - 使っている部品のライセンスの表示（THIRD_PARTY_NOTICES.txt）を、`build/make_notices.py` で作り、配布物に添える。部品を足したり版を上げたりしたら、作り直す。exe には、部品が「あれば使う」形で読み込もうとする、使っていない部品（numpy・lxml 等）が入りうるので、`build/motfax.spec` の excludes で外し、exe に実際に入った部品（ビルドの作業フォルダの PYZ-00.toc・PKG-00.toc）と表示を一致させる（2026-11-17。外した結果、exe は約 68MB〔Ver130〕から約 30MB になった）。
  - `tests/test_license.py` で、src と requirements.txt に、合わない部品（img2pdf・PyMuPDF など）がないことを確かめる。開発のときだけ使う道具（アイコンを作る `build/make_ribbon_icons.py` の PyMuPDF）は、exe に入らないので対象外とするが、Ver200 で別の手段に替えるかを検討する。

## 7. 技術構成

| 用途 | 採用技術 | 選定理由 |
|---|---|---|
| 言語 | Python 3.x | 開発方針。mintsツールと共通 |
| PDFラスタライズ | pypdfium2 | 外部バイナリ（Poppler等）不要でexe同梱が容易 |

| PDF情報取得・ページの組み立て | pypdf | ページサイズ・暗号化判定等のメタ情報取得、ページの表（F-01）からのPDFの組み立て（ページの並べ替え・回転の属性）、画像PDFの組み立て（F-12） |
| GUI | tkinter | Python標準。exeサイズへの影響が小さい |
| ドラッグ＆ドロップ | tkinterdnd2 | ファイルを開く・ページを追加する（F-32・F-33）。通信の機能はない |
| exe化 | PyInstaller（onefile） | 単一exe配布の実績が豊富 |

想定exeサイズ：30〜50MB程度。

## 8. 処理フロー

```
[開く／コピーして開く] … PDF（又は画像）を読み込み、ページの表を作る
    ↓
[事前診断] … ページ数・用紙サイズ・色・テキスト有無・大きさを判定し表示
    ↓          処理の選択は、既定設定の値を初期状態とする（自動では切り替えない）
[ページの編集]（必要なとき）… 追加・削除・並べ替え・回転。元に戻す・やり直す
    ↓          編集の都度、事前診断とプレビュー（変換イメージ）を更新
[ユーザーが処理内容を確認・選択] … 圧縮方式・容量超過時の処理方式・用紙正規化
    ↓
[保存／名前を付けて保存]
    ├─ 確認：［保存］（上書き保存）のたびに（F-03）
    ├─ 圧縮方式「何もしない」→ ページの表のとおりに、ページをそのまま並べる（回転は属性）
    │                           → 制約に合わない点は、止めずに知らせる（F-14）
    └─ 圧縮方式「二値化」「グレースケール」
         ├─ 検証：ページ数上限超過（プロファイルに上限がある場合）→ エラー停止（F-14）
         ├─ 検証：プロファイル対応外サイズかつ正規化OFF → エラー停止（F-14）
         ↓
       [ページごとの処理ループ]
         ├─ ラスタライズ（200dpi。利用者の回転を反映）
         ├─ 用紙正規化（プロファイル対応外サイズのみ中央配置。大は縮小・小は原寸維持・横向きは回転）
         └─ 二値化（G4） または グレースケール（JPEG）
    ↓
[PDFの組み立て] → [容量判定]
    ├─ 上限以下（プロファイル値）→ 書き込み
    └─ 上限超過 → 容量超過時の処理方式による（F-13）
                  ・解像度・品質を下げて再実行 → 全ページ下限到達でも超過ならエラー案内
                  ・分割して再実行 → _1of3 等を書く（開いたファイルは変えない）
                  ・何もしない → そのまま書き、超えていることを知らせる
    ↓
[書き込み] … 同じフォルダに一時的な名前で書き終えてから置き換える（F-02）
    ↓
[完了表示・保存した結果をプレビューに表示]
```

### 9.1 開発中に実施する事項（ローカルで実施可能）——**実施済み（2026-07-29完了）**

### 9.2 公開後に利用者フィードバック等により確認する事項（運用課題）

以下は本ツールの開発者が実環境を持たないため公開前の確認が実質的に不可能な事項である。ただし、本仕様は確認によってではなく設計によってこの不確実性を処理している（デフォルトは最保守形式の1bit白黒・G4、未確認値は「参考」区分としてUI注記、初回テスト送信の推奨をREADMEに明記）ため、未確認のまま公開して差し支えない。公開後、VBAアセット掲載ページ・支援者向けメール等で利用者からのフィードバックを募り、確認が取れ次第プロファイル定義・注記・掲載文を更新する（F-27の外部JSON構造により、プロファイル更新はexeの再ビルドなしに配布できる）。

1. **グレースケール受理可否（MOT/FAX）**：確認が取れるまでグレースケールは注記付きオプションに留める。
2. **テキスト付きPDF送信失敗の再現**：確認が取れるまで、掲載文の訴求文言は断定を避けた表現とする。
3. **eFax・jFaxの容量上限（合計1MB）の公式裏付け**：確認が取れ次第「参考」から「検証済」へ格上げし、UI注記を解除する。
4. **03FAX・faximoの公表仕様**：仕様表が確認でき次第、同梱プロファイルに追加する。

## 10. 対象外事項（本版のスコープ外）

1. Word・Excel等、PDF・画像（JPEG・PNG）以外の形式からの直接変換（画像の取り込みは、Ver200 で対象にした。F-34）
2. 複数ファイルの一括処理
3. FAX送信操作そのもの（各サービスへのアップロード・送信は利用者が当該サービス側で行う）
4. TIFF形式での出力（PDF出力のみとする。必要性が確認された場合にv2で検討）
5. 変換履歴CSV（全案件のファイル名をツール管理領域に一元蓄積する構造が守秘設計原則N-06に反するため見送り）
6. 公表仕様を確認できていないサービスの同梱プロファイル（03FAX・faximo等。仕様表の確認が取れ次第v1.xで追加。当面はカスタムプロファイルで対応）
7. macOS用の実行ファイルの配布と、macOSでの動作の保証（主要対象環境をWindowsとするため。標準プロファイルのMOT/FAXもMac非対応である。ソースからの動作のみN-03で対象とする。2026-10-25 班長決定により改める）
8. ページの中身の編集（文字・図の書き込み、注釈、墨消し、切り抜き）と、OCR（F-09・F-33）
9. 変換レポート（Ver200 でなくした。旧F-25）
10. 「最近使ったファイル」の一覧（ファイルの名前と場所を設定ファイルに残さないため。F-32・N-06）
